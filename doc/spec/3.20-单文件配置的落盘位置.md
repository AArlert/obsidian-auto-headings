# 3.20 单文件配置的落盘位置：frontmatter 的定位（2026-08-09 立场修正）

**背景**：0.x 起本插件的对外措辞一直是「配置在设置里、不进笔记」，README 亦如此承诺。竞品
gurjar1 走的是另一条路——单键 DSL `auto-heading: first-level 2, style 1.A.1, start-at 3, skip-h1`
一行承载单文件全部格式覆盖，纯函数解析、非法值静默忽略，另配一条「把当前设置保存到 frontmatter」
命令。2026-08-09 复核该实现后，作者修正了原立场。

**修正后的立场**（作者拍板）：

1. 原先那条「不进笔记」**是个人审美偏好，不是产品论证**，不必当作硬约束守着。frontmatter
   作为单文件配置的**持久化载体**是合理的——它跟着笔记走、跨设备、用户可见可改可版本控制。
2. 但**不接受把手写 DSL 当作使用插件的主要入口**。判断依据很直接：**用户没有那么多精力去学和写
   一行 DSL**。一个需要先读文档才能用的配置语法，对绝大多数用户等于不存在。
3. 因此定位是：**frontmatter 是落盘格式，不是配置界面**。
   - 写入侧的**主入口必须是 GUI 或命令**（例如「把当前设置保存到本文件」这类一键写回）；
   - 读取侧要容错：键缺失 / 非法值一律回退到全局设置，绝不报错阻断；
   - 手写只作为**高级用户的兜底能力**存在，**不得在 README 里当作卖点或主要用法售卖**。

**通用判据（适用于任何新功能，不止本条）**：**用起来轻松才是正道**——评估一个功能时先问
「用户要不要为此付出学习或输入成本」，需要付出的那部分必须有等价的一键路径兜底。
