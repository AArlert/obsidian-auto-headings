# 3.10 清除编号

编号是写进文件的**真实文本**，因此单靠删模板、删路径规则或取消勾选（frontmatter `false`）都**不会**抹掉已有编号（它们只停止后续自动编号，已有前缀**冻结现状**）。当用户确实想让某文件回到「无编号」的裸标题时，需要一个**主动剥离**动作。

**三个入口：**

| 入口 | 范围 | 行为 | 防误触 |
|------|------|------|--------|
| 命令「清除当前文件编号」 | 仅当前活动文件 | 剥**全部**编号（含插件自己写的 WJ 编号），还原裸标题；**并顺带暂停该文件**（1.0.15，见 [3.19](./3.19-单文件暂停与不抢键盘.md)）——否则下一次按键就被编回去，这条命令等于摆设 | 直接执行（单文件、可撤销，风险低） |
| 命令「清理非本插件的标题编号」（**0.6.6 新增**） | 仅当前活动文件 | **只剥「不含 WJ」的手写 / 外来编号**，**保留**插件自己写的（带 WJ）编号 | 直接执行（单文件、可撤销） |
| 本篇菜单「清理手写编号…」（1.2.2–1.2.4 为编号维护 TAB 的「清理非本插件编号」**[检查…]**，1.2.5 起搬进本篇菜单，见 [3.24](./3.24-笔记内入口.md)） | 仅当前笔记 | 同上，但先弹清理预览确认框逐条勾选（与迁移守卫同一个框，J14 / J17），确认后剥离并按模板重编；没命中模板时只剥离 | 有预览、可逐条取消；本篇改动可 Ctrl+Z 撤销 |
| 本篇菜单「自动编号：这篇不编号」（1.2.5） | 仅当前笔记 | 写 `false` 并剥掉**带 WJ 的本插件编号**（手写编号不动），取代原先菜单 / 面板上的「清除当前文件编号」入口 | 可 Ctrl+Z 撤销剥离（属性仍是不编号＝冻结现状） |
| 面板按钮 **[清除全库编号]**（编号维护 TAB） | 全库所有 `.md` 文件 | 剥**本插件写的**编号（含残缺前缀与降级残留）；不带插件痕迹的标题一个字节不动，结果提示报带手写编号的篇数（未发版，testplan H24——批量、未打开的文件撤销不了，又常是卸载前的清理） | **二次确认对话框**（1.2.2 起须输入确认词「清除」/ clear）；刻意**不注册为命令**，避免快捷键 / 命令面板误触发大面积改动；所在的「危险区域」**默认折叠**（M6），点击标题才展开，进一步降低误触 |

> **「清理非本插件的标题编号」为何而生（0.6.6，配合方案A）：** 方案A（见 [2.4](./2.4-保留正文起头的数字.md)）下，插件**只管理自己写的（WJ 标记）编号**，对用户**手写 / 导入**的伪编号（`## 1. X`、`## 第三章 X`、`## 1.2 X`）一律当正文、不再吸收。于是用户导入带手写编号的文档时，需要一个主动命令把这些**外来编号**清掉，好让插件接管。该命令逐标题判断：**含 WJ → 本插件的，不动**；**不含 WJ → 用更广的手写编号剥离器**（`stripForeignNumbering`：覆盖 arabic/cjk/带圈/字母/罗马 + `第…章` + 成对括号 `(1)`/`（一）`/`[1]`/`【1】` + `1.`/`1)`/`一、` 等惯例）剥一层。**已知风险**（与「清除编号」同源、属预期）：以序号样字开头紧跟分隔符的真实标题可能被误剥（`2024 总结`→`总结`）——本命令是用户**主动**一次性操作，已接受（未发版起只剥「确定」，`2024 总结` 只算「存疑」，见下文「按置信度分级」）。**1.3.1 修（testplan J27 / J28）**：字母样式只认**单个字母**（`a.` / `A)` / `(a)` 这类手写惯例），`git 相关`、`git commit 和 git push 的时机`、`GPG 签名策略`、`API 设计`、`TODO 清单` 这类**拉丁词开头的正常标题**不再被当成字母序号——此前它们不只在清理命令里被删字，更会被迁移守卫判成「像外来编号」而拦掉整篇文件的自动编号。同理，**字母 / 罗马序号后只跟空格不算编号**（testplan J28）：罗马字母能拼出大量真词（`vim 配置`、`XML 解析`、`CLI 工具`、`MVC 架构`，连规范罗马数字判定也挡不住——`CLI`=151），单字母 + 空格（`C 语言`、`B 站`）与单字母连字符词（`K-means`）也多是正文；须带标点或括号（`a.` / `A)` / `(a)` / `iv.`）才认。代价：多字母手写编号（`aa.`）与「罗马 + 空格」（`IV 结论`）不再被认，属可接受取舍。「清除编号」随后也对不带 WJ 的标题采用同一口径（见下方剥离器一段，testplan H22）。

**行为：** 逐个标题剥离本插件写入的编号前缀、**不再写入新前缀**，把标题还原为裸标题；其余文本不动。剥离以**单一事务**写回（全库版逐文件写回）。

**剥离器——「全样式并集」正则，独立于模板与 WJ。** 这是关键设计点：清除时文件可能**已无任何模板命中**（`/` 根规则、专属规则都被删了），没有「某个模板」可作剥离依据。故「清除编号」使用一个**不依赖具体模板、也不依赖 WJ** 的剥离器 `stripPrefixBroad`——它认得所有序号样式（arabic ∪ cjk ∪ circled ∪ 字母 ∪ 罗马）拼出的前缀 token，尽最大努力剥掉任何本插件可能写过的前缀（含 0.6.4 前无 WJ 的历史前缀、用户手写前缀）。**注意（方案A，0.6.6）：常规重排的 `stripPrefix` 已改为纯 WJ 边界（只剥带 WJ 的），而「清除编号」刻意仍用这个更激进的全样式正则**——因为「清除」的语义就是「把一切像编号的都抹掉」，与常规重排「只动自己写的」相反。「清理非本插件编号」命令则用介于两者之间的 `stripForeignNumbering`（更广的手写惯例正则，但只作用于**不含 WJ** 的标题）。

**未发版修（testplan H22，PR #11 讨论中 @smallerxie 指出）：全样式正则只用在有插件痕迹的残缺前缀上。** 此前「清除编号」对**完全不带 WJ** 的标题也套全样式正则（字母 `[a-z]+`、罗马 `[ivxlcdm]+`、分隔符含空格），于是没编号层级里的 `### vim 配置`、`## XML 解析`、`## C 语言` 被剥成 `配置` / `解析` / `语言`——用户想清的是编号，结果正文被删字，而本命令不弹预览。现按有没有插件痕迹分三路：
- 首哨兵、尾哨兵都在 → 精确剥到尾哨兵（本插件写的编号，含 `toAlpha` 写出的 `aa` 多字母序号，全走这里）；
- 首哨兵在、尾哨兵被毁 → 仍用全样式正则剥残缺前缀（有结构证据，宽规则才安全）；0.6.4–0.7.19 的旧单哨兵（WJ 前一段整段像编号）照旧剥到该 WJ 之后；
- **完全没有插件痕迹**（含中间只有链接锚点 WJ 的）→ 与「清理非本插件编号」同一口径：起初改用 `stripForeignNumbering`（拉丁词不算编号，J27 / J28），随后改为只剥整篇判定为「确定」的（见下文「按置信度分级」，H23）。——这一条只用于「清除当前文件编号」；「清除全库编号」对这类标题一律不动（H24）。

代价：0.6.4 以前写下、不带 WJ 的旧编号里，字母或罗马后只跟空格的（`a 备注`、`IV 结论`）与模板自定义前后缀包着的不再被清除；那批文件早该已被重编号换成 WJ 格式，影响可忽略。`2024 总结`、孤立的 `1.1 标题`（H5）随按置信度分级只算「存疑」，不再被直接剥。

> **与 frontmatter `false` 的分工：** `false`（取消勾选）= 「以后别自动碰我」（冻结、不清除）；「清除编号」=「现在把现有编号抹掉」（一次性动作）。二者常组合：**先「清除当前文件编号」抹掉，再取消勾选** 防止下次又被自动编号。**1.2.5 起**本篇菜单的「这篇不编号」把这个组合做成一步（只剥本插件编号）；手改 frontmatter 写 `false` 仍只冻结。
>
> **曾经的已知风险（未发版起不再成立）：** 用户**手写**的孤立 `1.1 标题` 曾被全样式剥离器误剥；现在不带 WJ 的标题只剥「确定」，孤立多段号只算「存疑」（H5 / J32）。

> **已修（1.2.0，testplan H8/H17）：** `clearAllVaultNumbering`（面板 [清除全库编号]）与
> `freezeVaultNumbering`（面板 [固化编号并交还所有权]）均改走批量通道 `batchRewrite`——已打开的文件走
> 它的编辑器事务（不读盘、不覆盖未落盘改动，可在该编辑器里撤销），未打开的走 `vault.process` 原子读改写，
> 与 M18 修复的竞态同源同解。顺带补上此前「清全库只刷新快照、不同步链接」的缺口：清除 / 固化时指向这些
> 标题的内链（同文件自链接与跨文件反链）随批量通道一并更新，跨文件反链的引用方若正被打开也走它的编辑器
> 事务、不读盘（见 [3.12](./3.12-Backlink同步.md) H18）。清库撤销（自建快照/还原）仍未做，见
> [Roadmap M11](./5-Roadmap.md#milestone-11--信任包插队-m8a-之前)。

## 按置信度分级（未发版，testplan J29–J34 / H23 / V80）

**问题**：单个标题只看形状，永远分不清 `a 备注` 与 `C 语言`、`1 红米` 与 `2024 总结`。此前每个标题单独套一条正则：
`2024 总结` 被清理命令剥成 `总结`、一个就拦下整篇的自动编号；1.3.1 为挡住拉丁词又放弃了 `a 备注`、`IV 结论`。
主力库实测（323 篇、3539 个标题）：旧正则命中 123 个、写入模式下守卫会拦 33 篇，其中「数字 + 空格」开头的 35 个
（`30 秒版`、`6 个 master`、`2027 年第一季度`）全是正文。

**做法**：`foreignassess.ts` 的 `assessForeignNumbering(content)` 给每个不带插件前缀的标题定档，预览框、两个清理命令、
迁移守卫、仅显示模式**只调这一个函数**。原则：自动动手的一档（直接剥 / 拦下整篇）必须证据确凿；拿不准就降档、交给
用户，不悄悄删字也不悄悄放过。

- **形状**（沿用 `stripForeignNumbering` 的正则，`matchForeignPrefix` 交出各组成部分）：
  - 强，单独即「确定」：`第三章`、`第1步`、`第一部分`、`（一）`、`(1)`、`①`、`一、`、`1.`、`1)`、`IV、`、`A)`、`C. 语言`；
    `步` / `部分` 只认 `第` 起头的，`3步`、`两部分` 是数量（J35）；
  - 中，单独为「存疑」：`1 概述`、`一 概述`、`C. elegans`（英文句点后跟拉丁字母多半是缩写）、多段号 `1.2 版本发布`；
    带前导词的不论后面跟什么都至多到这一档（J35）：`Step 1 安装`、`Chapter 2: 方法`、`Part II`、`Appendix A: 术语`、`§1 总则`。
    前导词是封闭短表（Step / Chapter / Part / Section / Lesson / Lecture / Unit / Module / Phase / Stage / Appendix / Week /
    Day，首字母大小写与全大写都认，及 `§`），连同序号一起剥；前导词算进读法签名，`Step 1` 与 `2 分析`、`Phase 2` 不互相成串。
    封顶为中是因为英文正文里也说 `Part 2 of the series`、`Section 3`；`Step 1` 恰是同级第 1 个仍按「值 = 序位」升为确定；
  - 弱，单独不算：字母或罗马后只跟空格（`a 备注`、`vim 配置`，J28），字母 / 罗马 + 冒号（`Q：…`、`ID：…` 是标签），
    读不出值的字母词（`CDC`）。连字符词（`K-means`）与剥完为空的纯编号标题（`# 第一章`，另见 J25；前导词 + 序号的
    `# Chapter 2`、`## Day 1` 同样算纯编号，J35）不当候选。
- **成串 → 确定**：同一父标题下、同一读法，序号元组从全 0 / 1 起（或以父标题编号开头、末段为 0 / 1），每步某一位加 1 或 2、
  其后各位归 0 / 1，至少 2 个；中间夹着的不相干标题跳过不断串。字母 / 罗马有歧义时各种读法分别试（`c` 可读 3 或 100）。
  序号值用 `renderNumeral` 渲染 1–99 反查（与渲染端天然一致），`vim`、`CLI` 查不到值、进不了串。
- **上下级对得上 → 父子都确定**：多段号去掉末段等于父标题的编号、末段为 0 / 1（`1 红米` / `1.1 工艺`）。
- **值 = 同级序位 → 确定**：中形状的单段序号，值等于它在同级里的位置（`1 红米` 是第 1 个；`2024 总结` 不是）。字母只跟空格
  不用这条（`A 股`、`C 语言` 恰好对得上位置的太多）。
- **否决**：数字后跟量词 / 单位（`秒`、`个`、`年`、`位`、`题`… 封闭短表）不用「值 = 序位」猜——量词只挡孤立标题的猜测，
  不挡成串与上下级，因为单字量词常是普通词的开头（`2 分析`、`1 项目背景`）；成串剥后同级重名整串作废（`A 计划` /
  `B 计划`、`I 型糖尿病` / `II 型糖尿病`）；字母只跟空格的串剥后都以同一个字起头，字母是修饰语，整串作废（`A 档 — …` /
  `B 档 — …`）；剥后与同级标题重名的（`Week 1 计划` / `Week 2 计划`，或旁边本就有个 `计划`）也不用「值 = 序位」猜，
  否则清除命令剥完就分不清谁是谁（J30，2026-11-05 补）。

**各入口**：

| 入口 | 确定 | 存疑 |
|------|------|------|
| 迁移守卫（写入模式自动路径、批量重编号） | 有一处即拦 | 不拦（「标题本身就是编号」仍按过半，J25） |
| 仅显示模式 | 确定与纯编号合计过半才不显示（V80） | 不计 |
| 清理预览框 | 列出、默认勾选 | 列出、**默认不勾**（J33）；一条都没勾且会套模板时按钮为「不清理，直接编号」 |
| 「清理手写编号」命令（不弹框） | 剥 | 不动，提示「另有 N 处看不准，未动」+「检查…」打开预览框（J34） |
| 「清除当前文件编号」不带 WJ 的标题 | 剥 | 同上，点开的预览框只剥不套模板——本篇刚被暂停（H23） |
| 「清除全库编号」不带 WJ 的标题 | 不动（未发版，H24：只清插件写的） | 不动；结果提示报带手写编号的篇数，指向本篇菜单「清理手写编号…」 |

**实测**（`node scripts/foreign-corpus.mjs <库>`，报告含标题原文、放 `doc/research/` 不入库）：主力库「确定」74 个
全是真编号（`一、`…`十四、`、`〇、`、`A.`…`F.`、`①`…`⑤`、`第一部`、`4.` / `4.1`…`4.6`），「存疑」34 个全是数量短语与一个日期，
守卫会拦的笔记从 33 篇降到 17 篇（剩下的都有真手写编号）。

**刻意不做**（评估过、代价不值）：重写逐字符扫描器与反向解析器；逐标题「这不是编号」的记忆（写入模式下插件写入的 WJ 编号
本身就是记忆——「不清理，直接编号」即接管，此后守卫不再问；记忆反而带来改名同步、多设备冲突、状态不可见）；标签页标题栏
图标、标题右键「清理此标题」、叠号自检、预览框依据小字。
