# 2.8 剪贴板净化设计（M11「复制净化开关」，2026-07-18 定案：同步净化 + 内存映射双通道）

> 承接 [2.6](./2.6-已知生态兼容性风险.md)「跨平台剪贴板投毒」一行与 Roadmap
> [M11「复制净化开关」](./5-Roadmap.md#milestone-11--信任包插队-m8a-之前)。本节是该功能的设计事实源。
> 定案历程：2026-07-10 初版双通道选型（OS 剪贴板 `"web "` 自定义格式做隐藏通道）→ 2026-07-15
> 真机 spike 判死「paste 事件语境读自定义格式」（实测记录保留在下方作历史依据）→ 2026-07-18
> 改为**内存映射双通道**最终定案并实现。
> **不含** Pandoc / 静态站点生成器 / Obsidian Publish 等**文件级**导出
> 场景——那类工具直接读磁盘文件、不经过剪贴板事件，本节的钩子对它们无效，其现状与缓解已由
> [M11「导出验证矩阵」](./5-Roadmap.md#milestone-11--信任包插队-m8a-之前)与
> [附录 A §A.5](./A-方向审查与否决理由.md#a5-导出拷问调研项的姿态太被动)单独覆盖（结论：Pandoc 场景不是 WJ 问题、是
> burn-in 语义冲突，靠导出前清除命令 / 契约 Lua filter 解决，非本节范围）。

**范围边界**：只覆盖**交互式复制 / 剪切 / 粘贴**（浏览器原生 `copy`/`cut` 事件 + Obsidian
`editor-paste` 事件）。`navigator.clipboard.writeText()` 等编程式写入（其他插件调用）、拖拽
（`dragstart`/`drop`）、Linux 中键主选区、文件级导出工具均不经过这些事件，拦不到，不在范围内。

**方案总览（2026-07-18 定案）——同步净化 + 内存映射双通道**：出口净化与回程还原都只依赖**同步**
可用的标准剪贴板格式。关键洞察：「这段粘贴内容是不是我们净化过的」这一判断**不需要问 OS 剪贴板**
（spike 已判死那条路，见下方历史依据）——净化是插件自己做的，把 `净化文本 → 原始文本（含 WJ）`
的映射记在**插件内存**（会话级 LRU）里，粘贴时同步读 `text/plain`（paste 事件语境同步可读，
spike 顺带证实）、同步查表即可。相当于隐藏通道从 OS 剪贴板搬进插件内存，2026-07-10 的双通道
设计目标全部保留，spike 判死的仅是通道的存放位置。

- **copy/cut 端（出口净化，`src/clipboard.ts` + main.ts 接线）**：全局挂 `copy`/`cut` DOM 监听
  （`registerDomEvent(document, …)`，主窗口一份 + `workspace.on("window-open")` 给每个弹出窗口
  再挂一份），**冒泡阶段**执行——此时更深层的处理者（CM6）已跑完，按 `evt.defaultPrevented`
  分两条路：
  1. **已被接管（编辑器路径）**：CM6 的 copy/cut 处理器会把选区文本 `setData("text/plain")` 后
     `preventDefault()`（剪切的选区删除也由 CM6 完成）。我们同步 `getData("text/plain")` 读出
     原文，含 WJ 才介入：净化后 `setData` 覆写 `text/plain`（如已写入 `text/html` 一并剥 WJ），
     并把 `规范化(净化文本) → 原文` 记入内存 LRU。不改 `defaultPrevented` 状态、不删其他格式，
     对 CM6 与其他插件最小侵入。
  2. **未被接管（阅读模式等原生默认复制路径）**：读 DOM 选区（`getSelection().toString()`），
     含 WJ 才介入：自行构造净化 payload——`text/plain`，外加从选区 `cloneContents()` 序列化并
     剥 WJ 的 `text/html`（保留阅读模式复制到富文本编辑器的格式）——再 `preventDefault()`。
     **此路不记 LRU**：渲染文本不含 `##` 标记，粘贴回编辑器不可能构成标题行，无 O9 风险，
     还原无意义。
  - 触发守卫沿用 2026-07-10 定案：只做 `.includes(WORD_JOINER)` 同步廉价判断、不做结构解析；
    净化 = 剥净全部 WJ 字符，对任意字符串成立，选区横跨标题 + 正文同样整体处理。
- **内存映射（隐藏通道的替代，2026-07-18 裁定）**：payload 沿用 2026-07-10「存完整原文、不做
  差异编码」的定案（理由不变：省空间无真实约束；「外部改过再粘贴回」本就该走降级路径），但
  存放处从 OS 剪贴板自定义格式改为**插件内存 LRU**——条数上限 + 总字符量上限，超限逐出最旧；
  键为换行规范化（`\r\n`/`\r` → `\n`）后的净化文本，值为原文。**只存内存、不持久化**：把用户
  复制的任意文本写进 data.json 有隐私顾虑，且跨会话的过期映射本就该「当新内容处理」。
- **paste 端（回程还原）**：挂 `workspace.on("editor-paste")`（Obsidian 给插件的官方粘贴拦截口，
  时序先于编辑器默认粘贴）。全部判断**同步**完成，任一守卫不过即放行原生管线、零影响：
  1. `evt.defaultPrevented`（其他插件已处理）→ 放行；
  2. `getData("text/plain")` 为空或规范化后查 LRU **未命中** → 放行（外部内容 / 图片 / URL /
     表格等对其他插件完全透明）；
  3. 命中但**目标文件编号未生效**（全局开关关 / frontmatter `false` / 无模板命中，复用
     `shouldAutoTrigger` + `getTemplateForFile` 的自动路径门）→ 放行净化文本——此时没有编号
     引擎兜底，还原反而把 WJ 重新引入用户声明「别碰」的文件；且引擎不跑也不存在双重编号；
  4. 多光标（`listSelections().length > 1`）→ 放行（原生多光标粘贴有按行分配语义，不模仿）；
  5. 全部通过 → `preventDefault()` + `editor.replaceSelection(原文)`：WJ 完好、编号仍是「被
     认领」状态，后续防抖重编正常改写序号，**不产生双重编号**（O9 命中路径消失）。
- **无开关（1.0.16 起）**：净化恒开，设置面板不再提供「复制净化」开关，`sanitizeClipboard` 字段
  随迁移从 `data.json` 删除（曾显式关掉的用户升级后同样恒净化）。理由：**「不把隐形字符塞进用户
  剪贴板」是插件的固有承诺，不是可选项**——留着开关等于承认「关掉也算一种正当配置」，而那个状态
  下 WJ 会外泄到微信 / 知乎 / Notion，正是 §2.6 登记的风险本身；M11 信任包要把它从「披露」升级到
  「主动消解」，一个默认开的开关只是消解了一半。行为面本就可控：WJ 守卫保证不含编号的复制粘贴
  零介入，降级路径保证任何失败都退回「等于本功能不存在」。
  > 1.0.10–1.0.15 曾有单开关 `sanitizeClipboard`（默认开，同时门控两端）。

**历史依据：paste 事件语境读不到自定义格式（2026-07-15 真机 spike）**：在真实 Obsidian 桌面
客户端（Electron 37.10.2 / Chromium 138.0.7204.251，Windows）DevTools Console 实测：
① `event.clipboardData.types`（同步）与 ② `paste` 事件处理函数内的异步
`navigator.clipboard.read()` 都**只见 `text/plain`**，`"web "` 自定义格式完全不可见（`read()`
正常 resolve、无权限提示，`getType()` 抛 `NotFoundError`——Chromium 对 paste 事件语境的既有
安全限制，非本地环境异常）；③ `keydown` 拦截后在事件外 `read()` **能**读到自定义格式（写入
本身成功，只是 paste 语境不暴露）；④ 但 keydown 方案要求无差别接管所有 Ctrl+V 并对未命中者
合成 `ClipboardEvent('paste')` 重派（`isTrusted=false`），跨插件兼容风险（实测环境即有依赖
paste 事件的 `obsidian-paste-image-rename`）与功能定位不成比例，且盖不住右键菜单粘贴——否决。
据此判死「OS 剪贴板隐藏通道」路线；本节内存映射方案正是绕开该限制的替代。原「Electron
`clipboard` 模块 writeBuffer 单格式限制（issue #41462）」「Async Clipboard API + `"web "` 前缀
自定义格式」两条选型调研随该路线一并作废，仅留此存档。

**移动端**：2026-07-10 调研确认移动端 WebView 沙箱拦截的是**异步 Async Clipboard API 的自定义
格式写入**；本方案已不使用该 API——copy/cut 端只用同步 `clipboardData.setData` 写标准格式，
预期移动端同样可用（待实机验证，登记 O10）；任何 `setData` 抛错走下述降级，行为等同旧方案的
「静默完全跳过」。

**降级默认值**：copy/cut 端任何一步失败（`clipboardData` 缺失、`getData`/`setData` 抛错）一律
不 `preventDefault`、不改写，剪贴板维持现状（仍含 WJ，等于本功能不存在）；paste 端任一守卫不过
即放行原生管线。介入永远「全有或全无」，不存在「改了一半」的中间状态。

**残余已知限制（O9 缩圈后的剩余面）**：LRU 未命中的粘贴——在外部编辑器改动过的文本、Obsidian
重启后、条目被逐出（上限见 `clipboard.ts`）、跨设备 / 跨 vault 实例——走「当新内容处理」降级：
落进文件的是**净化文本**，即「看得见的序号 + 没有哨兵」，与用户手写的外来编号在字节上完全等价。
这是 2026-07-10 定案时就接受的降级语义（这类场景本就该当新内容）；命中路径（最高频的 vault 内
直接复制粘贴 / 经外部中转未改动粘贴回）已由还原兜底，不再产生双重编号。

**后果分两种，取决于目标文件里有没有哨兵**——`hasUnclaimedForeignNumbering`（`cleanup.ts`）的
首行判据是「全文含任一 WJ 即返回 `false`」，所以两者**互斥**，不会同时发生：

| 目标文件 | 迁移守卫 | 实际后果 | 严重度 |
| --- | --- | --- | --- |
| **已有插件编号**（含 WJ） | 不触发 | 裸序号被 `stripPrefix` 当作正文，重排时在其前叠加新前缀 ⇒ `## 1 1 概述` 式观感 | 难看但活着：文件照常参与自动编号，用「清除当前文件编号」再重编即可复原 |
| **全文无 WJ**（尚未编过号的笔记） | **触发** | 该文件的自动编号被整个跳过，仅**首次**弹一条 Notice，此后静默持续跳过直至用户清理或重载插件 | **更重**：用户视角是「插件在这个文件里坏了」，且没有任何持续线索 |

第二种才是真正的暴露面，且**它的入口不止粘贴**——任何让文件进入「有可见编号、无哨兵」状态的
途径都会命中，日常打字即可（迁移守卫的误伤面：`stripForeignNumbering` 的
`upper-alpha` token 是 `[A-Z]+`、分隔符类含空格 ⇒ `## API 设计`、`## TODO 清单` 这类**完全正常的
标题**同样被判成「像外来编号」）。因此该问题的正解不在剪贴板侧，而在**让被拦状态可见、并给出
一条不吃用户内容的修复路径**（清理命令自身带同一误伤面，不能无预览地一键执行）。
