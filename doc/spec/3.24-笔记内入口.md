# 3.24 笔记内入口与命令（M16，1.3.0）

**目标**：用户不必进设置面板，就能在笔记里完成「这个标题别编号」「这一节升一级」「这篇换个模板」这类单篇操作。
所有入口共用同一批执行函数，命令、右键菜单、标题手柄、状态栏菜单只是不同的触发面。场景见 testplan S 组。

## 单标题与整节改写（纯函数，`headingedit.ts`）

- **跳过标记切换**：`toggleSkipMarker(line)`——无标记则在行尾补 ` <!-- skip -->`（规范形态，见 [3.21](./3.21-单标题跳过编号.md)），
  有标记（含大小写 / 内部空白变体）则整段连同前导空白移除。这就是 3.21「写入侧没有入口」那条的入口。
- **整节升降级**：`planSectionShift(content, line, delta)`——小节范围 = 该标题到「下一个级别 ≤ 它的标题」为止；
  只改 `parseHeadings` 认得的标题（围栏 / 注释里的 `#` 行不动）；范围内任一标题越出 1–6 级则整体拒绝（`null`），不做部分改写。
  结果是整行变更集，调用方并入**同一个** `editor.transaction`，一次撤销。

## 单篇模板与自动编号

- 单篇模板：frontmatter 键 `obsidian-auto-headings-template`（字符串，模板名）。解析优先级：该属性指向存在的模板 → 路径规则模板。
  属性指向不存在的模板时忽略（不报错、不清除）。选择器第一项「跟随路径规则」删除该属性。**只在路径规则命中且不是「不编号」时生效**——模式（写入 / 仅显示）仍由路径规则决定。
- 自动编号三选一沿用既有键 `obsidian-auto-headings`（true / false / 缺省，见 [3.2](./3.2-单文件开关.md)）；写入走
  `fileManager.processFrontMatter`。

## 入口

| 入口 | 内容 |
|------|------|
| 命令 | 跳过 / 恢复光标处标题的编号、升级 / 降级当前小节、为当前笔记选择模板…、开关当前笔记的自动编号；现有命令统一「动词 + 对象」命名，命令 ID 不变 |
| 编辑器右键 | 只加两项：跳过 / 恢复此标题的编号、复制本节链接 |
| 状态栏 | 桌面端「本篇」小标签，点开原生 Menu（见 S14） |
| 标题手柄 | **复用 Obsidian 原生折叠箭头**（不另造控件，见 S16/S17/S24）：单击照旧折叠、按住拖动移动整节、右键打开标题菜单；手机端光标进标题行时行尾「⋯」；阅读视图里只有右键菜单、不能拖（1.2.5，见下文） |

原生 Menu 无子菜单（obsidian.d.ts 1.13.1），多选一用勾选项或 SuggestModal。

## 标题手柄：复用折叠箭头（testplan S16/S17/S24）

用户 2026-10-07 实测后定：手柄不单独做一个控件，而是给 Obsidian 标题左侧悬停时出现的折叠箭头
（`.cm-fold-indicator`，`.cm-line` 的子元素）加功能。

- **单击**：原生折叠 / 展开，不拦截。
- **按住拖动**（位移 ≥ 5px 才算）：整节（含子标题）移动，落点用一条横线标在最近的「某标题行之前 / 文末」；
  拖到编辑区上下缘自动滚动；松手一次事务（一次撤销）。落在自身小节内或紧贴其后无效。**只搬位置，不改级别**。
  文本计算是纯函数 `moveSection`（`headingedit.ts`）。拖动后浏览器补发的那次 click 被吞掉，避免顺手折叠。
- **右键**：打开标题菜单（标签行 / 跳过 / 升级本节 / 降级本节 / 复制本节链接 / 本篇编号设置…）。
  「本篇编号设置…」打开本篇菜单，最下方有「返回」回到标题菜单。
- 箭头悬停提示一句「拖动可移动整节 · 右键打开菜单」。
- 手机端没有悬停，沿用行尾「⋯」浮层 → 原生底部菜单。

## 自动编号三选一的存储

「自动编号：跟随全局 / 这篇始终编号 / 这篇不编号」就是 [3.2](./3.2-单文件开关.md) 的单文件开关，**存在这篇笔记自己的
frontmatter 里**（键 `obsidian-auto-headings`：缺省 = 跟随全局，`true` / `false`），不进 `data.json`；
菜单只是读写它的入口。单篇模板同理存在 `obsidian-auto-headings-template`。

## 模板编辑增强（testplan S20–S23）

- **改动即时生效**（与 1.2.2 一致，用户 2026-10-07 定，推翻了先前的草稿式保存设想）：每次改动存模板并重编
  已打开的笔记；底部仍是「完成」。**退出编辑窗口视为一次保存**——样式相对打开时变过，就记进历史。
- **样式**（`templates/styles.ts`）：模板里决定编号长相的字段——各级格式、起止层级、起始数字、跳级策略、祖先序号渲染；
  不含名称与白名单，所以套用预设 / 恢复历史不会冲掉白名单。
- **快速套用**：格式页顶部菜单，含「最近用过的样式」（本模板历史里最近 4 份，勾选标出与当前相同者）和预设
  （数字层级 / 章节 / 公文 / 法律条文 / 大纲）。套用即时生效。
- **此模板的历史**：关闭编辑窗口时若样式变过，把新样式记进 `data.json` 的 `templateHistory[模板名]`（最新在前，最多 8 份，
  相同样式去重提前）；历史为空时先把打开时的样式记一份，保证能回到第一次编辑之前。模板改名时历史随键迁移，删除时清掉。
  「历史」弹窗列出全部快照，可恢复。
- **「不编号」挪到模式下拉**（S23）：路径规则的「模式」下拉为 写入文件 / 仅显示 / 不编号；选「不编号」时模板下拉置灰，
  数据仍是伪模板 `$none`（零迁移）。用户选什么就是什么；从「不编号」切回时模板退回默认模板。

## 本篇菜单收纳当前笔记的维护操作（1.2.5，2026-10-23 用户定，testplan S29–S32）

「编号维护」TAB 原有「当前笔记」一组（立即重新编号 / 清除当前文件编号 / 清理非本插件编号 / 清除残留编号）。它们隔着设置窗口
操作一篇看不见的笔记，而且「立即重新编号」「清除残留编号」本篇菜单里已经有了。用户定：**笔记的事在笔记上做，设置页只放全库的事**——
这一组整体搬进本篇菜单，「编号维护」TAB 只剩「整个仓库」两项（见 [3.13](./3.13-设置面板多TAB.md)）。命令面板里的同名命令不变。

本篇菜单（状态栏「本篇」、标题菜单的「本篇编号设置…」同一份）分四段：

1. 命中规则（标签行，不可点）；
2. 自动编号三选一：跟随全局 / 这篇始终编号 / 这篇不编号；
3. 换个模板… / 立即重新编号 / 复制编号大纲；
4. 清理：「清理手写编号…」（原「清理非本插件编号」，先弹清理预览框逐条勾选，J14 / J17）；**仅显示**笔记另有「清除残留编号」。

**「这篇不编号」顺手清掉本插件写的编号**（取代原「清除当前文件编号」的菜单入口，不再单列）：原先选它只写 `false`、已写入的编号
冻结现状，用户还得另找「清除」。现在选它（菜单与命令「开关当前笔记的自动编号」切到关时都一样）= 写 `false` + 剥掉这篇里
**带 WJ 的本插件编号**（`stripPrefix` 口径，手写编号不动——与命令「清除当前文件编号」的全样式剥离不同，后者照旧）。
想保留编号文字、只是不再让插件管：Ctrl+Z 撤销这次剥离即可（属性仍是「不编号」）；全库层面另有「固化」。
从「不编号」切回跟随全局 / 始终编号照旧立即重编。笔记里没有本插件编号时只写属性。仅显示笔记本就不往文件写编号，
选它时若文件里有残留（带 WJ）也一并清掉。手写 frontmatter `false` 的行为不变（仍是冻结现状，见 [3.2](./3.2-单文件开关.md)）。

图标：清理手写编号 `filter`（其余见上文 S28）。

## 阅读视图里也能用标题菜单（1.2.5，2026-10-23 用户定，testplan S33–S35）

阅读视图里标题左侧同样有原生折叠箭头（`.heading-collapse-indicator`）。**右键它打开与编辑视图同一份标题菜单**，单击照旧折叠；
**不能拖动**（阅读视图没有编辑器光标与落点，整节移动只在编辑视图做），箭头悬停提示相应只写「右键打开菜单」。菜单里改文件的项（跳过此标题 / 跳过整节 / 升级本节 /
降级本节，以及「本篇编号设置…」里的各项）在阅读视图下照常生效：阅读模式下 MarkdownView 仍持有编辑器，改动走它的事务（可撤销），
阅读视图随即刷新（实现见 `readingheadingmenu.ts`）。阅读视图 DOM 不带行号且区块懒渲染，按 DOM 序号对应不可靠：标题行号取阅读视图
渲染器的 `getSectionInfo(el).lineStart`（与公开的 `MarkdownPostProcessorContext.getSectionInfo` 同一实现），取不到时按标题文字在全文
**唯一**匹配，对不上就不弹菜单。同一篇**又在别的叶子里编辑着**时改那个编辑器（S35 ②，2026-10-24 真机抓出：各叶子的编辑器各存一份缓冲，
阅读视图那份不含别处未落盘的编辑，改它会让两边各自落盘、后存的盖掉先存的），行号按标题文字与同名序号映射过去；本篇菜单的单篇操作同理
（`markdownContextForPath` / `activeMarkdownContext` 优先编辑视图）。手机端阅读视图暂不做（没有悬停，
长按标题文字归 Obsidian 自己），留待真机反馈。

## 2026-10-07 二轮实测后的增补

- **两种跳过标记**（S26）：标题菜单 / 右键菜单 / 命令各有「跳过此标题的编号」（`<!-- skip -->`）与「跳过整节的编号（含子标题）」
  （`<!-- skip-tree -->`，见 [3.21](./3.21-单标题跳过编号.md)），勾选项反映当前类型，互斥。
- **复制本节链接 / 复制本节嵌入**（S27）：后者 `![[文件#标题]]`，不带别名（嵌入里 `|…` 是尺寸）；菜单、右键、命令三处都有。
- **本篇菜单的选项带 Obsidian 原生图标**（S28，与标题菜单同为 Lucide 图标，随主题着色）：map-pin 命中规则 · repeat 跟随全局 · circle-check 这篇始终编号 ·
  ban 这篇不编号 · file-text 换个模板 · refresh-cw 立即重新编号 · clipboard-list 复制编号大纲 · filter 清理手写编号（1.2.5）· eraser 清除残留编号 · undo-2 返回。
- 路径规则表里「当前笔记圆点」放在拖拽手柄**之前**（L46）；模板编辑弹窗给实色底，避免半透明主题下看不清（L47）。


## 升降级范围、阅读视图落盘、返回键与开关（未发版，2026-10-27 用户反馈，testplan S36–S39）

- **调整层级（取代「升级 / 降级」菜单项）**：标题菜单里两项带右侧子菜单，列 H1–H6，直接选目标层级——「调整此标题的层级」只改这一行（`scope: "self"`），
  「调整整节的层级（含子标题）」连同子标题整棵移动（`tree`）。起因：四个 `##`，把第一个升成 `#` 后后三个成了它的子标题，再降级就带着它们一起变
  `###`，用户觉得不跟手；「本节」语义本身没错，所以两种范围并列给出。**越界的层级置灰**（`reachableLevels`）：整节按最深的子标题限制，不压扁、
  不记状态，回去就选回原层级，树形从属永远无损（评估过「压扁到 H6 再回溯」：回溯要记原结构、任何其他编辑后还得作废，状态成本高，弃）。
  子菜单用 `MenuItem.setSubmenu`（不在公开 API 里），认不出时退化成平铺的「标题 · H1…」几项。命令「升级 / 降级当前小节 / 当前标题」仍在，供热键用。
- **阅读视图改文件走文件本身**：阅读视图背后的编辑器只是缓冲，往里 `transaction` 不保证落盘与重绘，用户实测「除复制链接 / 嵌入外都没用」。
  只在阅读视图打开的笔记改走 `vault.process`（`readingheadingmenu.ts` 的 `fileBackedEditor` 替身，菜单代码不分叉）；同篇另有编辑视图时仍改那个
  编辑器（S35 ②）。代价：这类改动进不了编辑器撤销栈。
- **「返回」置底并对准**：从标题菜单点「本篇编号设置…」进的本篇菜单，「返回」放在最下面（与上级菜单里「本篇编号设置…」同在末尾），弹出后整体上下挪到它正对鼠标——按**点击菜单项**的坐标定位，不是最初右键的坐标（旧版用后者，所以对不准）。
- **两个开关**（设置 → 全局设置 →「菜单」：标题菜单 / 状态栏菜单，说明各一句话，默认开）：`headingMenuEnabled`（右键折叠箭头 / 手机「⋯」/ 编辑器右键里的标题项）、
  `statusBarMenuEnabled`（状态栏「本篇」标签）。关掉不影响命令；放在设置里也是在告诉用户有这两个入口。
