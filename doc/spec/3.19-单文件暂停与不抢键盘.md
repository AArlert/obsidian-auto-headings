# 3.19 单文件暂停与不抢键盘（1.0.15）

本节三项修复同源：**插件在用户明确表态之后仍然自作主张**。

## 「清除当前文件编号」此前是摆设

`runClearNumbering` 只取消了该文件**当前那一个**待处理的防抖计时器，用户下一次按键即重新
`scheduleRenumber`、把编号原样编回去。也就是说只要「全局自动编号」开着，这条命令**永远不可能
产生持久效果**——用户看到 Notice 说「已清除编号」，几秒后编号回来了。

**修法**：清除时若该文件**确实**还会被自动重编号（`shouldAutoTrigger` 够格 + 命中模板），
把 frontmatter `obsidian-auto-headings: false` 并进**同一个** `editor.transaction`，一次撤销整体回退。
反之（全局关且非 `fm:true`、或路径规则解析为「不编号」）不写——不为一个不存在的问题往用户文件里
塞属性。恢复走「立即重新编号」，它顺带移除该键，构成 清除↔重新编号 的对称闭环；该键是 frontmatter
里唯一一项时整个 `---` 区块一并移除，不留空壳。

复用既有的单文件开关而非新造一份暂停状态，理由是它**写在文件里**：用户看得见、改得动、跨重启存在，
且每条自动触发路径本就尊重它。新造一个内存态 / 设置态的 `pausedPaths` 则是隐形状态，还要额外挂
文件重命名事件去重映射路径——正是 [3.18](./3.18-固化编号并交还所有权.md) 那条「插件不能在用户不知情
时一声不吭地什么都不做」的教训所指。

写入侧是 `frontmatter.ts` 的 `planPauseFileSwitch` / `planResumeFileSwitch`：它们只产出**整行级的
编辑计划**（从第几行起、吃掉几行、写入哪几行）而不直接改字符串。因为 `writeLineDiff` 按「整文件
重写永不增删行」的前提做逐行索引比对，往顶部插几行会让其后所有行错位；交回调用方翻译成一条
`EditorChange` 后，CM6 变更集按原文档坐标计算，与行替换天然互不干扰。

## `fm: false` 的含义收窄为「不自动**编号**」

上一条让「清除编号」开始写 `fm:false`，而该键此前**同时**关掉了 backlink 独立触发
（`shouldBacklinkStandaloneTrigger`）——意味着清一次编号会连「改名不断链」一起停掉，等于用一次
清除编号换掉了插件在 [附录 A](./A-方向审查与否决理由.md) 里定位的第一价值。

故 1.0.15 起 `shouldBacklinkStandaloneTrigger` 不再检查该键：**编号是可选进阶功能，链接同步是全局
能力，两者正交**。要让插件对某个文件彻底静默，关 `updateBacklinks` 总开关。这是对已上架语义的
有意收窄，testplan I8/M22 已相应改写。

## 不在用户正敲字的那一行下手

`stripPrefix` 会把标题文本的行尾空白归一化掉（`strip.ts` 的 `\s+$`，幂等所必需）。但自动路径此前
**没有任何光标守卫**：用户在标题末尾敲一个空格、停顿超过防抖时长，那个空格就被静默吃掉，接着打的
字直接贴上去——观感是插件在跟自己抢键盘。

**初版修法（1.0.15）**：自动路径把光标所在行的改动从本次事务里剔除（`preserveLine`），**其余行
照常重排**，该行等光标移开后的下一次触发补上。手动命令（立即重新编号 / 打开文件即重排 / 改模板
即时重排）不受保护。

关键接线：保护**必须发生在折叠自链接之前**——保护改动的是最终落盘内容，改名表与快照都得基于它
算，否则会据一份并未真正写入的内容去改写内链、或在下一轮识别出幻影改名。

## 换掉「整行冻结」这个手段（1.0.23，testplan J19）

整行冻结自 1.0.15 起连续暴露出同一类症状，根子是**用一个整行级的手段去解决一个只关乎行尾
空白的问题**：该编的号也一并被扣住了。而扣住之后的解除条件——「光标移开后的下一次触发」——
**根本不成立**：自动路径只挂 `editor-change`，**单纯移动光标不触发任何事件**，用户必须再编辑一次
才会补上。真机反馈的两种症状同源：

1. 改标题层级后等不到新编号（1.0.23 开发中曾用「层级相对 `headingSnapshots` 是否变化」的判据
   挡住这一种）；
2. **新敲出的标题不编号，除非按 Enter**——层级判据挡不住：新增标题会让标题数量相对快照变化，
   逐位对照的前提被打破而走保守分支，照样整行冻结。故该判据在同版内即被换掉。

**1.0.23 起不再冻结任何东西**，只把用户刚敲下的行尾空白补回本轮结果（`preserveCursorLineTrailingSpace`），
编号照常写入。判据不再需要快照或任何历史推断，只看这一行现在有没有行尾空白：

- 有 → 补回去，本轮结果 = 新编号 + 用户的空白，两个诉求同时满足。
- 没有 → 什么都不做，照常写入。

幂等性天然成立：补回后的行与上一轮落盘内容逐字节相同，下一轮算出同样结果即无改动可写（不发空
事务、不刷撤销历史）；光标移开后那一轮不再补，空白按既有归一化规则清掉。补回的空白也不会造成
幻影改名——`parseHeadings` 的 `text` 字段本就去尾空白，快照与改名判定看的都是它。

**配套：写回改为最小范围改写。** 不再冻结意味着光标所在行会在用户正敲字时被改写，而原先的**整行
替换**其变更范围**覆盖光标位置**，CM6 无从知道光标该落在替换文本的哪里，只能甩到一端——这是换一
种形式的「抢键盘」。故 `writeLineDiff` 改经 `lineChange()` 掐掉两端公共前后缀，只覆盖真正变化的
那一段：编号前缀落在行首（纯插入），用户光标在行尾，两处天然不重叠，位置映射自然保住。切点两端
各回退一格避开 UTF-16 代理对，免得 emoji 标题被从中间切开产生半个码位的坐标。这同时缩小了
[J6](../testplan.md)「编号写回不该移动光标 / 打乱选区」的暴露面。

## 附带修掉的迁移守卫误伤（testplan J12）

写 J11 用例时撞出来的既有缺陷：`hasUnclaimedForeignNumbering` 拿 `stripForeignNumbering(rawText)` 与
`rawText` **直接**比较，而前者末尾也带一道 `\s+$` 归一化。于是一个**全文无 WJ、无任何编号**的文件，
只要某个标题行尾有空格，就被判成「像外来编号」⇒ 该文件的自动编号被整个拦下，并弹出误导性的
「请先执行『清理非本插件的标题编号』」。修法：比较基准同样去掉行尾空白，守卫只对**真的剥掉了
编号**的情形生效。
