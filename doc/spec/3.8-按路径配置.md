# 3.8 按路径配置

路径规则在插件**设置 GUI** 中管理——**一张可视化表格**，每行将一个路径模式映射到所选模板（通过下拉框选择）。某路径命中专属模板时，该模板**整体覆盖**（包含其各级格式与白名单）。

**根规则 `/` 即「全局默认」。** 不再单设「全局默认模板选择器」；取而代之，表格里一条**路径模式为 `/` 的规则**充当全库兜底——它匹配仓库下所有文件，是具体度最低的规则。首次启用时插件预置一条 `/` → 「默认」规则，于是开箱即对全库生效；用户可把它改投任意自定义模板，也可**整行删除**——删掉后即「无全局兜底」，只有命中更具体规则的文件才编号，自由度交还用户。（「默认」模板本身始终存在、不可删，但**引用它的 `/` 规则可删**——两者是不同的东西。）

**GUI 布局：**

```
┌─ 路径规则 ──────────────────────────────────────────────────────────┐
│  ⚠ 无根路径规则（/），「全局自动编号」开启时部分文件将不被编号  │
│     [ + 添加 / 根规则 ]   ← 仅当不存在 / 规则且全局自动编号=开时显示  │
│                                                                     │
│  [+ 添加规则]                                                       │
│                                                                     │
│  #  │ 路径模式                   │ 模板                      │      │
│  ───┼────────────────────────────┼──────────────────────────┼───── │
│  1  │ /                          │ [默认       ▼]           │ [✕]  │
│  2  │ Projects/                  │ [技术文档   ▼]           │ [✕]  │
│  3  │ 读书笔记/                  │ [学术风格   ▼]           │ [✕]  │
│  4  │ 读书笔记/深度工作.md       │ [简洁风格   ▼]           │ [✕]  │
│                                   ↑ 可拖拽排序                      │
└─────────────────────────────────────────────────────────────────────┘
```

> **路径输入建议弹窗（1.0.3 重做 K13，1.0.11 加分层浏览 K14，1.0.12 统一 re-click 外观 K14b）：** 路径模式输入框接一个自绘的建议弹窗（`src/settings/tabs/PathSuggest.ts`），支持键盘 ↑↓/Enter/Esc 与鼠标点击/悬停；选中文件夹自动带上尾斜杠。**两种模式**，由 `browseDirForInput(value, folderPaths)` 依当前输入框内容决定：① **扁平模糊搜索**——输入框内容是**正在打字的片段**（如 `Pro`）、**文件规则**（无尾斜杠，如 `A/note.md`）、或**尚不存在的文件夹名**时，模糊匹配 vault 内**全部**文件夹 / 文件并排序展示（命中位置越靠前越优先，位置并列时文件夹优先于文件）；② **分层浏览**——输入框为空、为根 `/`、或已是某个**真实存在的文件夹**（尾斜杠，如 `A/`）时进入，只列出**当前层**的直接子项（文件夹优先、字典序），顶部 header 显示当前层路径且**点击即选中该层**（根层即「/」）、非根层额外一个 `⬅` 返回上一级，文件夹行右侧的小箭头 `▸` 用于**下钻**查看下一层（不选中，与行文字点击＝选中区分开）；一旦开始打字非文件夹片段即退出浏览、回到①，清空回空输入则重新从根开始浏览（不记忆上次下钻到的层级）。**为何模式判断不能只看「是否为空」（K14b）：** 1.0.11 初版只在输入框为空时进②，导致把某行配好 `/` 或 `A/` 后**再次点击该行**又回落到①的「匹配一堆」扁平列表（`/` 剥前导斜杠后 needle 空 ⇒ 返回全部，`A/` ⇒ 匹配一堆含 `a/` 的项），用户报告视觉/功能不统一；1.0.12 起改由 `browseDirForInput` 判断，`/` 与真实文件夹 `A/` 再次点击时同样进②（`A/` 浏览**进** A），与新增空行外观一致。**参考实现：** 弹窗交互与「输入框 + 文件夹建议」的匹配思路参考自 numeroflip/obsidian-auto-template-trigger 的 `FolderSuggest`/`TextInputSuggest`（挂在 `activeDocument.body` 上、`position: fixed` 定位，不受 `.ah-path-table` 自身纵向滚动裁剪影响，比原生 `<datalist>` 更可控）；直接读取其源码确认 `FolderSuggest.getSuggestions` 是**扁平**子串模糊匹配（非分层）、且用 `folder.path &&` **显式排除根目录**——本插件①的模糊搜索沿用同一思路，分层浏览是②在其基础上叠加的**新增能力**，两者不冲突（用户讨论定案）。**用户报告 bug 的根治：** 本插件把「文件夹规则」与「文件规则」的区分系于路径末尾是否带 `/`，手动输入时极易漏打（填 `Foo` 会被当成对一个不存在的同名文件的精确匹配规则，行为上像是「改了模板没生效」）；除建议弹窗选中文件夹时天然带斜杠外，`autocompleteFolderSlash`（`pathrules.ts`）在提交时兜底：只要输入去除前导斜杠后与某个**真实存在**的文件夹路径完全相等却缺尾斜杠，自动补全。**K14：** 早期版本手动注入一个合成根候选 `{path:"",isFolder:true}` 混进①的扁平候选池，一旦其自身路径恰好提交为 `/` 后再次聚焦，子串匹配会把这个候选自己排除掉、转而只剩「路径字面含 `/`」的深层嵌套项，顶层文件夹反而全部消失，观感诡异；`filterPathCandidates` 的 needle 也因保留前导 `/` 而把它当字面字符匹配。修复：①不再注入合成根候选（对齐参考实现，根规则改由②的 header 承接）；② needle 剥离前导 `/`（本就只是根锚点写法，非字面字符）。

> **列表可滚动 + 行内清空（M6）：** 路径规则过多时表格区可纵向滚动（表头吸顶），不再撑满整页看不全；每行路径输入框右侧有一个 **✕「清空此路径」**小按钮（只清空该输入框文本，**不**删除整条规则），与行尾**删除整条规则**的 ✕ 区分开。后者由按钮改为纯文本 ✕ 图标，不再被椭圆按钮背景包住。

> **兜底缺失提示。** 当表格中**不存在 `/` 根规则**、且「全局自动编号」为开时，面板顶部显示一条提示条「无根路径规则，部分文件将不被自动编号」，并附 **[+ 添加 / 根规则]** 快捷按钮——让「一堆文件突然不编号」这个状态**可见、可一键修复**，而非让用户困惑。这只是提示，不强制：用户确实想「只在特定路径编号」时无视即可。

**解析逻辑：**

1. 收集所有路径模式与当前文件匹配的规则（`/` 根规则匹配所有文件）。
2. **最具体的匹配**优先（精确文件路径 > 最长文件夹前缀 > `/` 根规则）。
3. **具体度并列**时（如两条不同文件夹名恰好等长），**行号更大**（列表中靠后）的规则胜出——这只是无法排出优劣时的确定性兜底，**不是**鼓励用法。
4. **若无任何规则匹配**（含 `/` 根规则已被删除的情形）：该文件**没有可用模板**。此时——**自动触发**静默跳过（不编号、不打扰、已有编号冻结不动）；**手动命令**弹 Notice「当前文件未匹配任何路径规则，无法编号」。frontmatter `true` 也无法凭空变出模板，故同样静默跳过（`true` 覆盖的是「触发资格」，不是「模板来源」）。

> **未配置行不等于根规则。** [+ 添加规则] 新增的一行路径模式初始为空串，代表「尚未填写」，**不匹配任何文件**——与用户显式填 `/` 表达「我要根规则」严格区分。曾经二者被等同处理，导致新增一行后只要先选了模板（尚未来得及输路径），就会被当根规则立即套用到全库并触发编号（testplan K11，0.7.22 修复）。

> **路径模式禁止重复（0.7.23）。** 两条规则的路径模式**归一化后完全相同**（含两条都填 `/`）却指向不同模板时，编号结果会取决于哪条「更靠后」这种用户在面板上看不出的内部顺序，体验上等同于随机、且用户报告确实造成过困惑。故 GUI 在提交路径编辑（新增一行填路径，或修改既有行的路径）时**主动阻断**：一旦归一化后与列表中其它某行重复，输入框回退为改前的值并弹 Notice「该路径已被第 N 条规则使用……」，不写入、不触发编号，逼用户先解决冲突（改路径或删掉其中一条）。这条约束**不分根/文件夹/文件**，任何路径模式的重复都拦；`resolvePathRule` 里"具体度并列时列表靠后者胜出"的兜底逻辑仍保留（应付历史遗留或手改 `data.json` 产生的重复数据），但不再是常规操作下会走到的路径。

> **「不编号」伪模板（M12，1.0.13，testplan K15）。** 每行模板下拉在真实模板之后固定多一个伪选项**「不编号」**（存储哨兵值 `$none`，见 `pathrules.ts` `NO_NUMBERING_TEMPLATE`；`TemplateStore.rename` 拒绝真实模板占用此名）：命中该规则的文件**彻底关闭编号**——文件夹级的 frontmatter `false`，替代逐文件维护。语义：伪模板**参与常规具体度解析并可胜出**（`daily/` 投「不编号」能压过根规则 `/`，不会被兜底回去）；命中后自动路径静默不编号、**已有编号冻结不动**（与 frontmatter `false` 相同，不主动剥除，想去掉用清除命令）；手动「立即重新编号」命中它时弹专用 Notice「当前文件所在路径已设为「不编号」」而非误导性的「未匹配任何规则」；模板删除/失效逻辑不把它当失效模板处理。实现上 `getTemplateForFile` 对哨兵直接返回「无可用模板」，复用第 4 条既有语义，改动面极小。

> **多文件批量重编号（M12，1.0.13，testplan K16）。** 路径规则表格每行一个行内 lucide `list-ordered` 图标按钮（M9 已定案的 UX：行内入口 + 确认对话框）：点击先弹确认框（显示该规则路径模式与命中文件数），确认后对**路径模式命中**的全部 Markdown 文件重编号（`batchRenumberRule`，main.ts）。语义要点：**每个文件用它自己解析出的最具体规则的模板**（与自动路径一致——点根规则的批量按钮不会把根模板强加给已被子规则接管的文件）；跳过 frontmatter `false`、含未接管外来编号（J10 迁移守卫同源判据）、解析为「不编号」/无可用模板的文件（批量一次作用于大量文件，尊重文件级显式关闭，不同于单文件手动命令的「绕过一切开关」）；**已打开的文件走编辑器单一事务**（可撤销，且避免 `vault.process` 读到未落盘编辑器内容的竞态——同 §3.12 同文件内链的根因），未打开的走 `vault.process`（无撤销，确认框已提示）；backlink 同步照常，跨文件改写总数**汇总为一条** Notice（`syncBacklinksCounted` 从 `syncBacklinks` 拆出的计数核心）；完成后汇总 Notice「改写 X / 无变化 Y / 跳过 Z」；命中 0 个文件不弹框直接 Notice；「不编号」规则行的批量按钮置灰。
