# 3.5 内部计数模型

插件维护一个计数器数组 `[c1, c2, c3, c4, c5, c6]`，分别对应 H1–H6。序号前缀只对
`>= topLevel` 的标题输出，并从 `c[topLevel]` 起截取拼接（如默认 `topLevel=H2` 时即 `[c2..c6]`）。

规则：
- 遇到第 *n* 级标题时，`c[n]` 加一，所有 *> n* 级的计数器归零——**即便该标题低于 `topLevel`**
  （它不输出序号，但仍归零更深级别，故是重置边界）。
- 计数器数组与显示格式（序号样式、间隔符）**相互独立**；格式转换仅在写入时进行。
- 白名单中的标题**不占用计数器槽位**——计数器既不累加也不归零，因此**不产生跳号**，且不向文件写入前缀。**例外（决策 D1，0.7.10）**：**子树**豁免块结束后计数器**整体重置**（独立结构语义，见 [3.7](./3.7-白名单系统.md)）。**注意**：若被「全部/部分」豁免的标题下还有子标题，这些子标题会沿用上一个已编号祖先的计数（通常非预期，应改用「子树」豁免整块，见 [3.7](./3.7-白名单系统.md)）。
- 跨级编号（如 `1.1.1`）由各父级计数器值用模板的**序号间隔符**拼接而成；**祖先段的序号样式由模板的 `ancestorNumeral` 决定**——默认 `self`（每级父级各自套用其所在级别的样式，得 `1.a.①`），或 `arabic`（祖先一律阿拉伯，得 `1.1`，适合中文书），见 [3.6](./3.6-模板系统.md)。**若某级关闭「继承前级」，则该级不拼接父级序号，仅以本级序号呈现**（如 H5 输出 `a)`、`b)`）。
- 内部计算全程使用纯阿拉伯整数，与模板指定的序号样式无关。
- **旧前缀剥离（方案A，0.6.6）**：重排前先剥掉上一次写入的前缀，再叠新前缀。`stripPrefix` 采**纯 Word Joiner 边界**——插件写出的每个前缀末尾都带一个不可见的 WJ（U+2060），剥离时只认它：**含 WJ → 精确剥到标记之后；不含 WJ → 整段视为正文、不剥**。这样无论序号样式 / 间隔符 / 前后缀怎么改，自己写的旧前缀都能被干净剥净（WJ 与这些字段无关），而用户正文里像编号的文字（`2024 总结`）绝不会被误吃。手写 / 历史（无 WJ）前缀由专门的「清理非本插件编号」/「清除编号」命令处理（见 [3.10](./3.10-清除编号.md)）。

**示例——内部计数器状态 vs. 写入文件内容**（默认模板：序号样式=阿拉伯，序号间隔符=`.`，标题间隔符=空格）：

```
标题序列              计数器状态            写入文件（模板应用后）
──────────────       ──────────────       ────────────────────────
H2                →  c2=1            →    1 标题
H3                →  c3=1            →    1.1 标题
H3                →  c3=2            →    1.2 标题
H2                →  c2=2，c3..=0    →    2 标题
H3（白名单）       →  c3 不变（=0）   →    （不写前缀，不占槽位）
H3                →  c3=1            →    2.1 标题   ← 未跳号
```

> **跨级拼接**：H3 的编号 `2.1` 由当前 `c2`（=2）与 `c3`（=1）以序号间隔符 `.` 拼接而来。**内部计数器始终是纯阿拉伯整数**，但拼接到前缀时**每一级父级各自套用其级别的序号样式**：若 H2 用中文、H3 用阿拉伯，则 H2 显示 `一`、`二`，而 H3 的前缀里父级 H2 也呈现为中文，得 `一.1`、`二.1`（而非把父级强制成阿拉伯的 `1.1`、`2.1`）。这样把 H3 设为字母、H4 设为带圈时，H4 能呈现为 `一.a.①`，父级样式向下可见。
