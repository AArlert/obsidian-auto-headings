┌──────────────────────────────────────────────────────────────────┐
│  main.ts（插件入口）                                             │
│  • 注册编辑器变化监听器                                          │
│  • 管理各文件的防抖计时器                                        │
│  • 全局开关 + 命令；读取 frontmatter 单文件开关                  │
│  • 加载 / 保存设置；首次启用时初始化 templates/default.json      │
└──────┬────────────────────────────┬────────────────────────────┬─┘
       │                            │                            │
┌──────▼──────┐           ┌─────────▼──────────┐      ┌──────────▼──────────┐
│  parser.ts  │           │  编号引擎           │      │  settings/           │
│  • 从原始   │           │  numbering.ts 编排  │      │  model.ts 数据模型   │
│    Markdown │           │  （对外 barrel）+   │      │  SettingsTab.ts GUI  │
│    解析标题 │  ──────►  │  template.ts 模型   │      │  • 全局开关          │
│  • 识别代码 │           │  count.ts   计数器  │      │  • 模板编辑器        │

                          │  whitelist.ts 白名单│      └──────────────────────┘
                          └────────────────────┘
                          （外部一律从 ./numbering 导入，拆分对调用方透明）

├── schema.ts            // 模板校验 / 序列化 / 文件名安全化
└── TemplateStore.ts     // 模板文件的增删改查（读写 templates/*.json，目录与默认模板自动创建）

pathrules.ts                // 路径 → 模板 的解析（含 `/` 根规则即全局默认；白名单随模板）——M5 已落地（纯函数）

> **M5 已落地**（见 [3.1](./3.1-开关命令与生效判定.md)/[3.8](./3.8-按路径配置.md)）：`main.ts` 的「全局开关」已拆成**两层**——「启用插件」（Obsidian 总开关）与「全局自动编号」（`settings.autoNumber` 面板开关 + 全局命令）；新增「自动 / 手动」两条生效路径判定（`shouldAutoTrigger` / `runImmediateRenumber`）与按路径解析模板（`getTemplateForFile`，纯解析见 `pathrules.ts`）。`SettingsTab.ts` 已落地路径规则表（含 `/` 根规则、兜底提示条、拖拽排序、`<datalist>` 补全）与删模板「知情确认 + 安全降级」对话框（`DeleteTemplateModal`）。
>
> **M6 已落地**（0.6.0，规格见 [3.10](./3.10-清除编号.md)）：`SettingsTab.ts` 的 [清除全库编号] 按钮（危险区域，默认折叠）与 `main.ts` 的「清除当前文件编号」「清理非本插件的标题编号」命令，共用 `cleanup.ts` 剥离器家族。
>
> **M7 多 TAB 已落地**（0.7.11，规格见 [3.13](./3.13-设置面板多TAB.md)）：`SettingsTab.ts` 改为壳（TAB 栏 + 分发），内容拆到 `settings/tabs/`（GeneralTab / TemplatesTab / PathRules / EditPanel / WhitelistEditor / DangerTab / AboutTab）；「危险区域折叠」由敏感操作 TAB 取代。

> **M8 规划中**（未落地，规格见 [3.14](./3.14-侧栏大纲导航.md)/[3.15](./3.15-拖放重排与结构编辑.md)）：计划新增
> `views/OutlineView.ts`（`ItemView` 子类，M8a）——目前 `src/` 内没有任何自定义 Leaf/View，这是第一次引入
> 该类基础设施；面板本身只读取 `numbering.ts`/`backlinks.ts` 已算好的结果做树形展示，不新增编号逻辑。
> M8b 的拖放重排如果落地，会在「整文件重写、从不批量扫库」的既有写入模型（不变）之上新增一种「结构性
> 剪切—拼接」的写入路径，建议实现为独立于 DOM 手势的纯函数（如 `moveHeadingBlock`），以便沿用
> `tests/dev_tests/uvm/` 的约束随机序列做回归，而不是只能手工点击验证。测试基建目前完全没有 DOM
> （`vitest.config.ts` 固定 `environment: "node"`，`obsidian-mock.ts` 的元素只是空对象）：M8a 落地时预期按
> 文件加 `jsdom` 覆盖树构建/搜索/键盘导航等结构性断言，M8b 的真实拖拽手势与动画效果仍在自动化覆盖范围之外。

> **触发的性能边界（设计澄清）。** 插件**只**在「当前活动文件的 `editor-change`」「手动命令」「设置面板改配置后对活动文件即时重排」三个时机触发，且每次只解析 / 改写**当前这一个文件**；**从不**为「应用了某模板的所有文件」做全库扫描。因此**没有打开、没有编辑的文件不会触发任何插件工作**，模板再多也不会带来后台开销——路径规则只在某文件被实际编辑 / 命令时按其路径解析一次（`getTemplateForFile`）。这与「整文件重写、从不批量扫库」的核心写入模型一致（见 [3.3](./3.3-写入文件模型.md)）。
>
> **M13 例外（1.0.26 起，标题链接建议）**：该功能的前缀匹配天然要求一份「vault 级标题 → 位置」索引，故在 `onLayoutReady` 后做**一次**懒加载的全库**只读**扫描（分批让出主线程，只建内存索引、不写入任何文件）；此后仅按文件增量维护（`editor-change` 去抖 / `vault` 事件）。这是全生命周期唯一一次全库扫描，且不随编辑/命令反复发生。

**存储分层：**

| 存储位置 | 内容 | 读写方式 |
|----------|------|----------|
| `data.json` | 路径规则（M5）、防抖延迟等插件设置（**不含白名单**——白名单随模板存于 `templates/*.json`） | `plugin.loadData()` / `plugin.saveData()` |
| `templates/*.json` | 各模板定义文件，每个模板一个文件 | `app.vault.adapter` 文件 API（`read` / `write` / `exists` / `mkdir`） |
