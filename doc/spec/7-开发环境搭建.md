# 7. 开发环境搭建

> 前置条件：Node.js ≥ 18，用于测试的 Obsidian Vault

```bash
# 1. 克隆到 Vault 的插件目录（文件夹名需与 manifest id 一致）
cd /path/to/your/vault/.obsidian/plugins
git clone <repo> auto-headings
cd auto-headings

# 2. 安装依赖
npm install

# 3. 启动监听构建
npm run dev

# 4. 在 Obsidian 中启用插件
# 设置 → 社区插件 → Auto Headings → 启用

# 5. 运行单元测试（无需 Obsidian 运行时）
npm test
```

> **热重载**：在开发 Vault 中安装 [Hot Reload](https://github.com/pjeby/hot-reload) 社区插件，每次 `main.js` 重新构建时可自动重载 `auto-headings`。

## 7.1 实机验证环境（Ubuntu + Obsidian 实体 + Claude Code，规划中）

> 2026-07-10 立项（用户决定）：后续开发迁至装有 Obsidian 桌面实体的 Ubuntu 环境、由 Claude Code
> 驱动。这补上纯 Node 测试基建（vitest + `obsidian-mock.ts`）覆盖不到的最后一环——真实渲染、真实
> `metadataCache`、真实导出管线、真实剪贴板——并一次性解锁 [M11](./5-Roadmap.md#milestone-11--信任包插队-m8a-之前)
> 的全部"待实测"项与 testplan O 组。首次搭建时按下列约定落实并回填本节。

**环境约定：**

1. **专用测试 vault**：仓库外新建（如 `~/vaults/auto-headings-test/`，**勿用真实笔记库**），
   `release/` 三件套软链或复制进 `.obsidian/plugins/auto-headings/`；装 Hot Reload 插件配合
   `npm run dev` 自动重载。测试样例直接投喂 `tests/user_tests/*.md`（本就是为复制进 vault 设计的）。
2. **驱动方式（推荐 → 兜底逐级降格）**：
   - **CDP 自动化（推荐）**：Obsidian 是 Electron 应用，以 `obsidian --remote-debugging-port=9222`
     启动后用 Playwright/Puppeteer **attach** 渲染进程，即可执行
     `app.commands.executeCommandById(...)`、读写 `app.vault` / `app.metadataCache`、截图——
     `user_tests` 的手工场景由此可脚本化为**实机回归**，agent 无人值守跑完整矩阵。
   - **obsidian:// URI + xdotool**：打开指定 vault/文件的轻量入口，配合键鼠事件做简单流程（CDP
     不可用时的兜底）。
   - **纯手动**：agent 给操作清单、用户照做回报（现状模式，降为最后兜底）。
3. **验证矩阵执行清单**（对应 testplan O 组与 M11 条目）：
   - O4 剪贴板：编辑器内复制后 `xclip -o -selection clipboard | hexdump -C` 直查 WJ 字节；
   - O5 导出：CDP 触发「导出为 PDF」+ `pdftotext` 核对编号完整性与 tofu；Pandoc 直转 /
     `--number-sections` / 契约 Lua filter 三种管线对比；
   - O2 外部写入：脚本绕过编辑器直改磁盘文件，模拟 Sync / git pull；
   - O3 共存：同 vault 先后启用 gurjar1 插件，记录互认现象；
   - M11 大库性能：脚本生成含 50+ 引用文件的合成 vault，计时改名同步与防抖写回；
   - README 截图 / GIF：CDP 截图补齐商店门面（长期占位项就此了结）。
4. **纪律**：实机驱动脚本与合成 vault 生成器入 `tests/machine_tests/`（新目录，落地时回填
   `log.md` 目录结构约定块与本节）；实机结论**只回填** testplan 对应行与 [2.6](./2.6-已知生态兼容性风险.md)
   状态列，不另开结论文档（单一事实源纪律）。
