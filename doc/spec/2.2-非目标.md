# 2.2 非目标

- **脱离编号引擎的渲染**（CSS 计数器之类）：「仅显示」的虚拟编号模式（[3.22](./3.22-虚拟编号模式.md)）与写入模式
  共用同一个编号引擎，模板、白名单、`<!-- skip -->`、层级范围语义完全一致，不另起一套纯渲染编号。
  （「仅注入渲染层」原为非目标，2026-09-25 翻案，理由见 3.22 与 [附录 A](./A-方向审查与否决理由.md) §8.5。）
- **往正文里生成物理目录的命令**（一次性插入 / 刷新一份目录文本）：不做；单文件目录走两条路，一是 burn-in
  （[3.16](./3.16-原生风格TOC-burn-in.md)，构思中），二是**只读渲染的 `ah-toc` 目录块**（[3.25](./3.25-只读目录块.md)，M17-B）。
  后者是用户手写一个围栏，插件只在阅读视图 / 实时预览 / PDF 里把它渲染成目录，**不写文件、不改块内容**，
  与本条「不生成物理目录」不冲突（2026-10-28 澄清）；它的价值是让仅显示模式的编号也能出现在目录里。
- **改写用户的标题层级**（插件只增删编号前缀，绝不把 `#` 改成 `##`；多个 H1 的"规整"交给用户/白名单）
- **跨文件聚合视图**（总索引、跨笔记聚合目录）：走 Roadmap M9「Dataview 集成」路线。单文件内的目录
  不在此列——0.7.28 翻案为 TOC burn-in（[3.16](./3.16-原生风格TOC-burn-in.md)），理由是 burn-in 真实文本别的插件做不到。
- 在 frontmatter 中存储任何**配置**（模板、白名单、路径规则刻意排除，以保持笔记整洁）；frontmatter 仅用作单文件开关
- Git 感知最小化差异（后续版本）
- 标题居中 / 自定义字体等**渲染层美化**（与「burn-in 写入」哲学冲突，明确不做；有此需求可用 Auto Heading）
