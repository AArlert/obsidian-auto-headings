# 3.22 虚拟编号模式（M14）

**定位**：与写入模式并列的第二种哲学（翻案见 [2.2](./2.2-非目标.md)，论证见 [附录 A](./A-方向审查与否决理由.md)
§8.5）。编号只在 Obsidian 里**显示**——编辑视图用 CM6 装饰，阅读视图用 post-processor——**永不写入文件**。
竞品对照（下载量见 [A.11](./A.11-竞品格局核验.md#下载量快照)）：Heading Decorator（纯显示，还能装饰内置大纲面板）、
gurjar1（有虚拟模式但默认写入，只在编辑器里显示）、Number Suite（虚拟 + 隐藏文件里已有的编号）、
Heading Keeper（默认虚拟，写入需明确开启）。本插件的差异点：**两种模式共用一个编号引擎，按路径规则
混用**，阅读视图与内置 PDF 导出也有编号，改名不断链在两种模式下都成立。

## 数据模型与生效判定

- `PathRule` 加可选字段 `mode?: "write" | "virtual"`（`src/pathrules.ts`）。**缺省即 `"write"`**，老数据
  零迁移；`loadSettings` 归一化时非法值回落 `"write"`。
- 纯函数 `resolveNumberingMode(rules, path)` 返回 `"write" | "virtual" | null`：取有效规则（与
  `resolvePathRule` 同一套具体度）的 mode；有效规则是「不编号」时返回 null。
- **frontmatter `true` 压不过「不编号」规则**：此时没有可用模板（[3.8](./3.8-按路径配置.md) K15 的既有行为），
  与写入模式一致——不写、也不显示。（周期 0 曾写成「强制编号、跟随根规则模式」，周期 1 核对代码后订正：
  那会凭空给「不编号」文件夹造出编号，与写入模式分叉。）
- **门控与写入模式完全一致**：清库中（retired）、frontmatter `false`、全局自动编号关闭、「不编号」规则
  → 都**不渲染**。
- **外来编号按「过半」判定**（真机实测后订正）：**超过一半**的标题像手写编号（`isMostlyForeignNumbered`）
  才整篇不渲染，打开时弹仅显示版的可点击提示；点开的清理框对仅显示文件**只剥手写编号、不写插件编号**。
  不沿用写入模式「一个就算」的判据：写入模式确认清理一次、插件写入编号后文件含 WJ，守卫就永久解除；仅显示
  模式永不写文件，没有这个出口——一个 `## 2024 总结` 就会让整篇永远没有编号。按过半判定后，从别的编号
  插件迁来、每个标题都带编号的笔记照样被拦下；偶尔以数字开头的标题照常编号，与写入模式（方案 A）一致。

## 新装与升级

- **判据**：`loadData()` 为空 **且** 插件目录下没有 `templates/` 目录 → 全新安装，根规则 `/` 的 mode 设为
  `"virtual"`；其余一律视为升级，不动 mode。理由：老用户可能从没改过设置（因此没有 data.json），但首次
  启用时一定建过 `templates/default.json`。
- **顺序约束**：`loadSettings`（onload 早段）必须在 `templateStore.init()`（负责创建 `templates/`）**之前**
  执行，否则判据永远失效。有单测锁住这个先后顺序。
- **多设备同步竞态**：第二台设备可能在 data.json 同步到位之前就加载插件，被误判为新装。对策：
  ① 新装分支只在内存里设 `"virtual"`，**不立即 `saveData`**，等用户第一次改设置时才落盘；
  ② 实现 `onExternalSettingsChange`（API 1.5.7+），data.json 被同步改写时重新载入并广播刷新渲染。

## 写入路径的隔离

- 虚拟文件不走任何编号写入：实现上是让 `shouldAutoTrigger` 对虚拟文件返回 false，于是 `scheduleRenumber`、
  打开即编号、立即重新编号、批量重编号、固化编号都自然跳过。
- **改名不断链照常成立**：`scheduleRenumber` 的入口是「`shouldAutoTrigger` 或 `shouldBacklinkStandaloneTrigger`」，
  后者只看 `updateBacklinks` 与清库状态（见 [3.12](./3.12-Backlink同步.md) CR-18），虚拟文件自动
  落到独立同步分支——用户手动改标题时，其他笔记里的链接照样跟随，**不新写同步路径**。
- 对虚拟文件执行「立即重新编号」＝只刷新显示，并弹 Notice 说明「此文件为仅显示模式」。
- **粘贴还原**（[2.8](./2.8-剪贴板净化设计.md)）在虚拟文件里不生效：
  还原的原文带 WJ 编号，粘进去等于制造残留，只接受净化后的文本。
- 「清除当前文件编号」用在虚拟文件上**不写 `fm:false`**：暂停是为了防止下一次按键又被编回去，虚拟文件
  本就不会被写回；写了反而会关掉它的虚拟显示。
- 门控判定抽成纯函数 `resolveNumberingAction`（`src/virtual/compute.ts`），渲染器与 UVM 记分板共用。
- 标题索引、链接建议、VC 联动不用改：虚拟文件的标题没有前缀也没有 WJ，`stripPrefix` 原样放行，锚点
  就是纯文本。

## 渲染

- **编辑视图（CM6）**：`registerEditorExtension` 注册 ViewPlugin。用 obsidian 导出的 `editorInfoField`
  取文件路径，经上述门控与模板算出 `numberHeadings`，在每个标题正文起点放一个 `WidgetType`
  （`<span class="ah-virtual-number">`，`eq` 按文本比较）。
  - 文档变化时先 `decorations.map(tr.changes)` 保证位置不漂移，完整重算放进约 100ms 的去抖。
  - 模板 / 设置 / 规则变化时，用一个 `StateEffect` 广播给所有已打开的编辑器重算。
  - **输入法**：`view.composing` 为真时不重算、不 dispatch，组合结束后补算一次——组合区旁的 widget
    被替换会打断中文输入。
  - **只在实时预览里显示**（真机实测后订正）：源码模式是给人看原文的，显示虚拟编号会让人以为编号已经
    写进了文件；残留前缀在源码模式里也照原样露出。用 `editorLivePreviewField` 判断，模式切换时立即重算。
- **阅读视图**：`registerMarkdownPostProcessor`，给 `h1`–`h6` 前插同 class 的 span；span 可反复加 / 去，
  剥掉的残留前缀记在 span 上，去编号时原样还回文本。
  - **Obsidian 只重渲染改过的段落**（真机实测：在前面插入标题后，后面没改的段落还挂着旧编号）。所以每个
    含标题的段落都登记成 `MarkdownRenderChild`，出现下列任一情况就把同一篇的所有登记段落按**各自当前的**
    段落信息重新核对、原地改编号（不整页重渲染，不闪）：有段落重新渲染且看到的原文变了；文件元数据更新
    （`metadataCache.on("changed")`，兜住「删掉标题但没有段落重渲染」）；设置 / 模板 / 规则变化。
  - 缓存按路径记住上次的原文与设置版本，**字符串直接比较**，不对整篇重复计算。
  - **小节嵌入**（`![[笔记#标题]]`、悬浮预览某一节）的段落信息只含这一段，编号若按它算会从「一」重数
    （真机实测）。所以先和文件全文比对：是全文里的一段 → 按全文算、行号加偏移；拿不到段落信息或对不上 →
    按标题文本唯一匹配兜底，对不上就不画，**宁缺勿错**。
  - 内置「导出 PDF」走阅读视图渲染管线，真机验证带编号。
- 样式 `.ah-virtual-number`：颜色跟随标题、`user-select: none`（阅读视图里复制不带编号；编辑视图的
  widget 本就不在文档文本里）。
- **内置大纲面板**（1.2.0，原二期候选，用户要求提前；testplan V40–V45）：大纲是核心插件视图，没有公开
  API，按 Obsidian 1.10 的实现（asar 里的 app.js）核对后这样挂：
  - 视图持有 `file` 与条目数组 `cachedHeadingDom`（文档顺序），条目带 `heading`（metadataCache 的
    `HeadingCache`）与 `innerEl`（`.tree-item-inner`）。按条目的 `heading.position.start.line` 取编号、
    再核对级别，对不上就不画；编号来自 `cachedRead` 的全文，与 metadataCache 解析的是同一份内容。
  - 大纲每次刷新都用 `innerEl.setText()` 重写文字，插节点会被冲掉，所以编号只写成 `data-ah-number`
    属性、由 CSS `::before` 画出，不碰大纲的搜索高亮、拖动与点击跳转。
  - 条目按需渲染（虚拟滚动），屏幕外的条目不在 DOM 里。编号挂在**条目对象**的元素上，滚进视口时自带；
    **不能**像 Heading Decorator 那样扫描屏幕上的 DOM 去对齐标题（滚动 / 折叠 / 过滤后会错位）。
  - 刷新入口 `requestUpdate` 在构造时捕获了原始 `update`，实例打补丁挂不住——改用 MutationObserver 看
    `childList` 变化（刷新会重写可见条目的文字），合并到一个微任务里核对全部条目；写属性不触发它，不自激。
    新开 / 关闭 / 延迟加载完的大纲靠 `layout-change` / `active-leaf-change` 挂上或摘掉观察器。
  - 以 WJ 开头的残留旧编号标题不画（大纲只能显示原文，叠上去是两层数字）。
  - 设置「在大纲中显示编号」（`showOutlineNumbers`，默认开）；关掉后插件对大纲零接触、已画的编号立即去掉，
    留作 Obsidian 改内部实现时的退路。结构认不出就什么都不做（失败静默），不影响编辑 / 阅读视图。

## 残留前缀

- **来源是常态**：删掉写入规则、改规则路径、改成「不编号」、把文件挪进仅显示文件夹，都会让已写过编号的
  文件落到仅显示模式，且其中文件移动不经过任何确认框。
- **渲染**：用 `Decoration.replace` 盖住旧前缀区间（行首 `#` 与空格之后，到第二个 WJ），只显示虚拟编号，
  绝不出现两层数字。
- **不许悄悄盖掉**：旧前缀仍在文件里，导出 / Publish / 外部编辑器看到的是旧编号。被盖住的标题改用
  `ah-virtual-number--stale` 样式（如虚线下划线），悬停提示「文件里还留着本插件写入的旧编号」；另提供
  命令「清除本文件残留编号」。
- 清库进行中（`vaultClearInProgress`）不渲染残留提示，清库结束后广播刷新一次。

## 切换模式

- **写入 → 仅显示**（在路径规则行上改 mode）：确认框写明「将清除 N 个文件中本插件写入的编号」，确认后批量
  清除。
  - 只处理**有效规则就是这一条**的文件（`resolvePathRule(file) === rule`），排除被更具体规则覆盖的文件。
  - 已打开的文件走编辑器事务，未打开的走 `vault.process`（复用批量重编号的两条通道，变换函数换成清除）。
    两条通道已带 backlink 同步，清除改了标题文本，其他笔记里的链接跟着更新。
  - **清除只剥带 WJ 标记的前缀**（新纯函数 `clearPluginNumberingContent`），用户手写的编号原样保留。
    **不复用** [3.10](./3.10-清除编号.md) 的清除命令路径：那条路径用「全样式并集」剥离（会剥手写编号）、会写
    `fm:false`（反而关掉虚拟渲染）、并走 `vault.modify`（H8 同类竞态）。
- **仅显示 → 写入**：不需要清除。确认框给一个可选勾选项「立即对这 N 个文件写入编号」，复用批量重编号；
  不勾就等下次编辑时再写。
- **取消确认 ＝ mode 不变。**
- **同一确认框的其他入口**：删除规则、改规则路径、把规则模板改成「不编号」时，若有 N>0 个文件的有效
  模式会从「写入」变为「仅显示 / 不编号」，同样弹框，并提供「保留编号（冻结现状）」选项。「不编号」
  沿用 [3.10](./3.10-清除编号.md) 的老语义，默认冻结现状。文件移动不弹框，交给残留提示处理。
- **实现（周期 3 定稿）**：不区分入口，一律比较「改动前 / 改动后」每个文件的有效模式
  （`src/virtual/modeSwitch.ts` 的 `diffNumberingModes`），拖拽排序也走同一条路。「离开写入」的文件只计
  **真有本插件编号**的（没有就不打扰）；三类都为空时直接生效。确认框用两个开关代替多个按钮：「清除本插件
  写入的编号」（只有改为仅显示的文件时默认开，涉及「不编号」时默认关）、「立即写入编号」（默认关）。
  规则在副本上试改，确认后才替换设置并落盘，再执行清除 / 写入；取消或 Esc = 规则原样。
- **新规则的模式跟随根规则**：根规则是「仅显示」时，「+ 新增规则」默认也是「仅显示」——否则新装用户
  一填路径就开始往文件里写编号，违背他们没做过的选择。
- 「仅显示」规则行的「批量重编号」按钮置灰（不写文件，无需批量编号）；「不编号」规则行的模式下拉框置灰。

## 与其他功能的关系

- **固化编号并交还所有权**（[3.18](./3.18-固化编号并交还所有权.md)）：**照常处理全部文件**，不跳过虚拟文件
  ——虚拟文件里指向写入文件标题的链接也带 WJ，跳过会让这些链接在固化后断掉；残留前缀也该一并剥净。
  代价要在按钮说明里写清楚：**仅显示的编号本就不在文件里，固化后随插件离场一起消失**。「把虚拟编号
  一次性烧录成纯文本」登记为 M9 候选。（周期 0 曾写成「虚拟文件跳过」，周期 1 订正。）
- **已知限制**（写进使用指南，不回避）：文件内搜索、Publish、GitHub、外部编辑器里**看不到**虚拟编号。
  内置大纲面板 1.2.0 起能看到（见上文「渲染」）；M8a 自建的侧栏大纲应直接显示虚拟编号。

## 代码组织

`main.ts` 已约 2170 行，虚拟模式新代码**不往里加**，放 `src/virtual/`：`compute.ts`（纯函数：原文 + 模板
+ 选项 → `[{lineIndex, label, burnedPrefixRange?}]`，node 可测）、`editorExtension.ts`（ViewPlugin /
StateEffect / Widget）、`readingView.ts`（post-processor 与缓存）、`modeSwitch.ts`（切换确认、命中文件
筛选、批量编排，通过接口回调 main.ts 的批量通道）、`outlineView.ts`（内置大纲面板的编号，1.2.0）。
main.ts 只加接线。验证场景见 testplan V 组。
