# 3.21 单标题跳过编号：`<!-- skip -->` 标记（issue #6，phase 1）

**需求来源**：用户 [issue #6](https://github.com/AArlert/obsidian-auto-headings/issues/6)（2026-07-29）。
白名单（[3.7](./3.7-白名单系统.md)）按**标题文本**匹配，是**跨文件**的一类词豁免；用户的场景是「这篇笔记里的
『临时讨论』不该编号，但同名标题在别的笔记里是正常章节」——需要的是**行级**豁免，白名单结构上
覆盖不了。

**标记形态**：写在标题行**末尾**的 HTML 注释 `<!-- skip -->`。大小写不敏感、容忍内部空白
（`<!--skip-->` / `<!--  SKIP  -->` 一律认）。判定见 `parser.ts` 的 `hasSkipMarker`。

四条选型理由：

1. **HTML 注释在阅读视图天然不可见**，用户不必为「让插件少做一件事」在正文里留下可见垃圾。
2. **不需要新开解析分支**：[3.17](./3.17-跳过区域.md) 的裁决 R2「行首定标题」已经保证
   `## 标题 <!-- … -->` **本行仍是标题**、且行内闭合不遮蔽下方——正是本标记需要的语义。
3. **必须在行尾**：出现在标题中间的同形字符串多半是用户在写批注，不该被当成指令（testplan E33）。
4. **与竞品 gurjar1 刻意同形**：两者本就声明不可共存（`marker-contract.md` §4），同形让从它迁移
   过来的用户的既有标记直接继续生效，迁移成本为零。

**语义（复用白名单的下游通道，不新造机制）**：命中标记的标题接到 `numbering.ts` 中**白名单豁免的
同一分支**上——「完全透明：不编号、不推进计数器、不作重置边界，但**剥离其已有编号**」。

- **不推进计数器**是关键：跳过的标题不占槽位，其后的同级标题编号**连续**（E30）。
- **剥离已有编号**同样关键：给一个**已编号**的标题事后补上标记，下一次重排会把那个编号**摘掉**，
  而不是把它冻结在原地（E31）——否则用户会得到一个永远不再更新的僵尸编号。

**未定项（phase 1 刻意不做）**：

- **只作用于本行、不含子树**（E34）。issue 原文提到「跳过该标题及其 subtree（或仅跳过自身，
  可配置）」，gurjar1 做成了可配置。phase 1 取最不意外的那一种；是否加子树选项等真实反馈。
- **写入侧没有入口**：phase 1 只做**识别**，标记由用户手写。一键切换要等标题旁浮动菜单 GUI
  （Roadmap M12 该条 phase 2）——按 [3.20](./3.20-单文件配置的落盘位置.md) 的判据，
  **手写只是兜底能力，不是主要用法**，README 不得把它当卖点售卖。
- **内链锚点的表现待实机确认**：带标记的标题，其 `rawText` 含 `<!-- skip -->`，因而 backlink 快照
  与锚点归一化看到的也是含标记的文本。Obsidian 自身的 metadataCache 是否把 HTML 注释算进标题
  锚点、`[[文件#标题]]` 补全会给出哪一种形态，**本地无法验证**，登记 testplan 待实机核对。
  当前实现**不对锚点做任何特殊处理**——与 Obsidian 的原始文本口径保持一致是最不容易错的默认。
