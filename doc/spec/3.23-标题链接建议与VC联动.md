# 3.23 标题链接建议与 Various Complements 联动（M13）

> **2026-08-11 立项**（完整实施方案见 `doc/research/` 本地调研留档，已按本仓库纪律留本地不入库）。
> 目标：把「输入即链接」变成默认能力——打字命中 vault 内已有标题原文即可 Tab/点按生成正确链接，
> 同时联动生态位更大的第三方补全插件 Various Complements（其自身「标题级补全」issue #72 开出 4 年多
> 未解决），以此触达其用户群，前提是联动本身足够稳健、不破坏用户已有的 VC 配置。
> **架构注**：全 vault 前缀匹配天然要求一份「vault 级标题 → 位置」索引，必然需要一次全库扫描
> （懒加载到 `onLayoutReady`）——与「从不为全库扫描」的既有承诺直接冲突，已随本里程碑修订
> （见 [§4 架构设计](./4-架构设计.md)「触发的性能边界」的 M13 例外）。

## 已落地的设计要点

> 验证见 testplan Q 组（真机手验项待回填）。

- 全 vault 标题索引（`headingindex.ts`：排序数组 + 二分查找、增量维护、内存/性能上限
  50,000 条 / 单文件 500 条、截断时一次性 Notice 不静默丢弃）
- `EditorSuggest` 建议框（`headingsuggest.ts`：前缀增量匹配、桌面 Tab + 移动点按接受、
  上下文屏蔽礼貌规则、IME 组合不触发）
- 链接锚点复用 `backlinks.ts` 的 `displayAnchor`，正确处理已编号标题的 WORD_JOINER；
  **1.0.27 产品决策**：接受建议时 alias 自动补全为剥编号前缀后的**完整标题名**
  （用户实测反馈「希望是完整的标题名而不是残缺的」，与 VC 词典 value 的 alias 形态一致）
- Various Complements 联动（`vcintegration.ts`：手动引导 / 自动配置两模式、分层防御写入、
  schema 校验失败整体放弃），两模式均需用户显式确认后才开启
- **VC 侧事实已对照源码核实（1.0.27，clone 留档 doc/research/vc-source-verification.md）**：
  词典 JSON 顶层必须是 `{"words":[...]}`（裸数组会让 VC 解析抛错、整个词典加载失败——这是
  用户实测「联动后打一个『交』无候选」的根因之一，1.0.27 已修复）；`customDictionaryPaths` /
  `enableCustomDictionaryComplement` 字段名与 reload 命令 id `reload-custom-dictionaries`
  全部确认；自动配置顺带把 VC 的 `customDictionaryMinNumberOfCharactersForTrigger` 置 1
  （VC 默认触发阈值 3，1–2 个字符不触发；1.2.4 起改为 2，见下文「VC 侧同步收紧」）
- **词典轻量三件套（1.0.27）**：紧凑 JSON（无缩进，20,000 条 ≈ 2.2MB 封顶）+
  内容未变不写盘（内存缓存比对，标题无变化时 iCloud/同步零流量）+
  词典独立条数上限 `MAX_VC_DICTIONARY_ENTRIES = 20,000`（超出截断 + 一次性 Notice）
- **启动词典同步（1.0.28）**：VC 只在启动与 reload 命令两个时机加载词典——已联动用户
  升级/重启后，插件在 `onLayoutReady` 主动重写词典 + 调 reload（2s × 5 次重试，耗尽静默）
- **M13 标题索引纳入 UVM 压测（1.0.28）**：`uvm/heading-index.ts` 参考模型记分板
  （朴素 Map + filter + 稳定排序对拍 DUT 的排序数组 + 二分 + 增量维护），随 `npm test`
  跑 500×60、`test:fuzz` 跑 5000×80；已抓出并修复 U5–U7（同 key 顺序不稳定 /
  rename 覆盖残留 / 自身改名计数漂移，见 testplan §3.3）
- **无标点连写的尾部词触发（Q22，1.0.29）**：中文正文没有词边界，触发词提取会把「一笔」
  和随后打的「事务」吞成一个 token，前缀匹配必然落空。匹配候选放宽为「整段 + 逐级后缀」
  取第一个命中（`headingtrigger.ts` 的 `suffixCandidates` / `resolveTriggerQuery`）。
  **关键约束**：`onTrigger` 的替换区间起点必须同步收窄到被匹配上的那一段，否则接受建议会
  吃掉前面的「一笔」——UVM 记分板每步断言 `start` 与 `text` 自洽。后缀的命中标准已由下一条收紧
- **触发规则：按信号而非长度（Q27–Q34，issue #10，1.2.4）**：用户反馈「随便打两三个字都弹框，
  空格还会误选」。根因是两层猜测叠加：2 个字符起就按前缀匹配，且行内后缀也按前缀匹配——任何一句话
  末尾两三个字碰巧是某标题开头就弹（「当前项目」→【项目级…】）。第一版改成「中文 3 字 / 英文 6 字母」
  的长度门槛，随即发现会把短术语（`axi`、`uart`、`cdc`）全部挡掉，推翻。定稿依据用户主力库实测
  （2026-10-18：272 篇、1987 个不同标题、85% 只在一个文件出现、310 个被链接过、167 个短标题里多是术语）：
  - **先筛**：同名标题出现在 ≥ `GENERIC_FILE_COUNT = 3` 个文件里视为套话（【边界】×24、【反问】×9），
    Excalidraw 绘图文件（`*.excalidraw.md` 或 frontmatter `excalidraw-plugin`）整个不进索引——两者
    都不触发、不进候选、不进 VC 词典（`HeadingIndex.isGenericKey` / `eligibleEntries` / `isExcalidrawFile`）
  - **再按规则表命中**（`headingtrigger.ts` `resolveTriggerQuery`；权重 = 中日韩字符记 2、其他记 1）：
    | 候选 | 条件 |
    |---|---|
    | 起于词边界、权重 ≥ `MIN_PREFIX_WEIGHT = 6` | 有标题以它开头 |
    | 起于词边界、权重不足、不含中日韩字符 | 完整等于某标题 |
    | 起于词边界、权重不足、含中日韩字符 | 完整等于某标题，且该标题被链接过 |
    | 连写中间的后缀 | 完整等于某标题，且（权重 ≥ 6 或被链接过） |

    「词边界」= token 开头，或中日韩字符与其他字符的交界（「用uart」里的 `uart`）。道理：前缀匹配是猜，
    输入量够大才猜得准；完整命中不用猜，但短词常是普通词——英文短词在中文笔记里多是有意打的术语，
    中文两字词靠「被链接过」证明它是概念（主力库里【中断】【cdc】被链接过，【使用】【其他】没有）
  - **被链接次数**（`headinglinks.ts`）：metadataCache 的 `links` 先解析到目标文件，再拿该文件索引条目
    的锚点比对（编号 / WJ 由条目自带 anchor 吸收），按 matchKey 汇总；按源文件分桶增量维护。也用于排序
  - **排序**（Q34）：完整命中 → 被链接多 → 当前文件 → 短 → 路径
  - Tab 接受加 `isComposing` 判定，组合中的 Tab 归输入法（Q29，与 Obsidian 自带 Enter 一致）
  - 「空格误选」核对过两侧代码均未绑定空格（Obsidian 1.10.6 app.js 建议框只注册 Enter / Tab 且判
    `isComposing`），疑与 Easy Typing 这类自动加空格的插件或输入法有关，复现见 Q38
- **按主力库重放数据再收紧（1.2.5，2026-10-24 用户定，Q30 / Q31 / Q62–Q64）**：脚本 `scripts/suggest-replay.mjs` 把主力库
  298 篇约 130 万字的正文用插件自己的触发函数逐字重放：1.2.4 规则每千字弹 18 次，真实写下的标题链接 1760 个，弹框约是它的 13 倍；
  常弹的是短术语与常用词（「验证」×1936、sv、axi、「为什么」、read、sequen）。比了 9 组方案（打扰 vs 召回 = 真实链接在原笔记里打出
  标题文字时能否弹出），静态规则越收召回掉得越多（中文前缀提到 4 字再降 20% 打扰，召回再掉 4 个点），最大的杠杆是「不选就记住」。定稿：
  - **短词都要信号**：权重不足的完整命中（不分中英文）要求该标题被链接过 ≥ `MIN_LINKS_FOR_SHORT = 2` 次，或就在当前笔记 / 同一文件夹里，
    或当前笔记链过它（`TriggerIndexProbe.isRelevant`）。「就近」的道理：同一个项目文件夹里的术语多半是你正在写的那件事
  - **纯英文前缀门槛 8 个字母**（`MIN_LATIN_PREFIX_WEIGHT`）：6 个字母时打普通英文单词（sequence、scoreboard）就会被前缀猜中
  - **不选就记住**（`headingsuggest.ts`）：框弹出后没选就关了（Esc、回车、接着打字），这次框开着时出现过的查询在这一篇里不再弹；
    切换到别的笔记即清空（回来重新算）。不持久化——它是「这一会儿别烦我」，不是长期偏好（长期偏好见 Roadmap M18「历史反应」）
  - 结果：每千字 18 → 12.6 次，加记住后至多 5.0 次；召回 79.9% → 75.7%。剩下的多是领域术语（sv、npu、时序），规则分不出用户此刻想不想链
- **VC 侧同步收紧（Q35–Q37，1.2.4）**：VC 的匹配本插件管不到，能管的只有词典内容与自动配置写的值——
  词典只放 `eligibleEntries`（同上筛选）；自动配置的触发阈值由 1 改为 `VC_DICTIONARY_MIN_TRIGGER_CHARS = 2`
  （只抬不降；老用户重选一次「自动配置」生效，不擅自改别的插件设置）。**推翻「切回不联动不做反向清理」**：
  不清理的话 VC 会一直加载这份不再更新的词典，标题改名后插入坏链接（用户主力库实况）。现在切回时若启用中的
  VC 还挂着本插件词典就问要不要移除（只删那一行路径，阈值等其余设置不回滚），「不联动」状态下发现残留则在
  面板常驻提示 + 「移除」按钮
- **一个「建议显示在」取代两个下拉（Q41/Q43，2026-10-18 用户定）**：用户的三种情况——① 只有本插件：「标题链接
  建议」开关即全部（新装默认关，1.2.5 起；见下文「开 / 关两档」）；② 本插件 + VC，选「本插件的建议框」：不写 VC 词典，本插件的框排在 VC 前面、
  盖住它；③ 本插件 + VC，选「VC 的建议框」：标题写进 VC 词典，本插件让路。原先「VC 启用时（让路 / 本插件优先）」
  +「VC 联动（不联动 / 手动 / 自动）」两个下拉能组合出「让路但没联动」（两个插件轮流抢弹框位）和「优先却开着联动」
  （两边的框都出标题）两种自相矛盾的状态，用户实测两边建议混在一起。现在**让路与否只看联动开没开**
  （`shouldYieldSuggestToVc(VC 状态, 联动模式)`），`headingSuggestWhenVcActive` 字段删除并随加载迁移清理。
  选 VC 弹自动配置确认框（框里另有「手动配置」按钮）；切回本插件走停止联动确认（Q35）；老用户按联动开没开自动
  对应到两个选项之一。本插件的建议框在加载与布局就绪时挪到 VC 的之前（`moveBefore`，只挪到 VC 前面，不动别的插件
  的顺序）——Obsidian 按注册顺序取第一个触发的建议框（`editorSuggest.suggests`），否则「盖住 VC」取决于加载顺序；
  让路时本插件 onTrigger 直接返回 null，排前面也不抢
- **输入法上屏后补触发一轮（Q44，2026-10-18 用户实测「ax 停一下再打 i 一直是 VC」）**：拼字期间编辑器里已经有拼音
  字母，Obsidian 照常触发（每次编辑后去抖 50ms，`editorSuggest.trigger` 按注册顺序取第一个），本插件按 Q9 在
  `imeComposing` 时返回 null，VC 便占了位；上屏若不改变文档（拼的就是英文）就不会再有编辑事件，本插件再没机会。
  `compositionend` 后经 `editorSuggest.trigger(editor, file, true)` 补触发一轮，顺序、互斥、关旧框都交给 Obsidian；
  该入口不在官方 API 里，认不出就静默。真机回归脚本 `tests/probes/suggest-timing.js`（用 CDP 模拟输入法）
- **词典更新要同步进 VC 内存（Q45，2026-10-18 用户实测「新写的标题在 VC 框里打不出」）**：VC 只在启动、重载命令、
  保存设置时读词典文件，1.0.27 起本插件改写词典文件后 VC 并不知道——只有开启联动那一刻与重启后的标题能进 VC。
  整体重读会把用户其他词典（常见的联网英文词表）一起重读重下，不可取；改为每次写词典后 `replaceVcDictionaryWords`
  只替换 VC 内存里 `createdPath` 为本插件词典的那部分：照 VC `refreshCustomWords` 的结构 `clearWords` + 逐个
  `addWord` 重建索引，新词条按 VC `jsonToWords` 规则构造并套用其正则过滤；全部校验在清空前做完，认不出不动，
  重建中途出错退回 VC 整体重读。顺带修启动顺序：启动同步原先不等索引建完就写出空词典
- **标题行里也给建议，只排除正在写的这一条（Q7 改写，2026-10-18 用户定）**：1.0.26–1.2.3 标题行整行不弹，为的是
  不把正在写的标题建议给它自己；但用户确有在标题里链到别的标题（含同一篇笔记的其他标题）的需要。`isBlockedContext`
  去掉标题行判据（只剩 `#` / `[[` / `[`），改由索引查询带 `ExcludeAt`（当前文件 + 当前行）剔除正在写的那一条
- **VC 的框也守本插件的规则、且对照实时索引（Q46/Q48）**：标题写进 VC 词典后由 VC 匹配，VC 不知道本插件的规则，
  也只认它内存里那份词典——用户实测：在 `# haha` 里打字，VC 把正在写的标题本身列成候选，选中后链接插进标题、越套
  越长；改了标题接着打字，VC 框里还挂着已不存在的旧标题。给 VC 建议框实例的 `getSuggestions` 套一层逐词判断
  （`installVcContextFilter` + main.ts `shouldDropVcWord`）：本插件词典的词在 `#` / `[[` / `[` 上下文、正在写的
  这一条、指向的标题已不在索引里（按词条 `description` 路径 + 插入文本里的锚点 `findByAnchor`）或已成套话时去掉，
  VC 自己的词照常。本插件 onTrigger 每次键入都先于 VC 跑，在那里自检补上（VC 重开换实例也能接上），卸载时还原；
  改的是 VC 的非公开结构，认不出就不套。过滤只能删不能加——新标题进 VC 仍靠同步：只在标题真的变了时调度（`setFile`
  返回变化与否；删除、改名也调度），且不重置计时（原先每次编辑都把 3 秒重置，不停手就永不同步），VC 内存
  `VC_MEMORY_SYNC_MS = 500`、词典文件 3 秒两个节奏
- **链接文本按 Obsidian 的规则，重名笔记写路径（Q47）**：原先一律 `[[文件名#锚点|标题]]`，库里有多篇同名笔记时
  Obsidian 解析到另一篇（用户实测：甲科技的【haha】链到了汇顶那篇）。本插件建议框用
  `metadataCache.fileToLinktext(目标, 当前文件, true)`；VC 词典不知道将来插在哪，以空源路径求（重名一律写路径）
- **改 VC 设置一律走 VC 自己的 `saveSettings({ customDictionary: true })`（Q39）**：VC 的词典提供者缓存了路径列表，
  只在 `updateSettings` 里刷新，只 `saveData` + 重载命令读到的还是旧路径（用户实测：移除后 VC 框里仍有 2610 条标题；
  同理自动配置新加的词典要重启才出现）。该方法不在官方 API 里，缺失时退回 `saveData` + 重载命令
- **与 VC 的建议框共存策略（Q23，1.0.29）**：Obsidian 的 `EditorSuggest` 同一时刻**只显示
  一个**弹框，本插件与 VC 抢同一个位置——1.0.28 及以前本插件恒优先，VC 自己的文件链接建议
  整个看不见（用户实测截图）。新增设置 `headingSuggestWhenVcActive`：**默认 `"yield"`**
  （VC 已启用时本插件不触发，标题建议改由 VC 框经词典联动统一呈现），`"own"` 恢复旧行为。
  **1.0.31 起让路还要求词典联动确实开着**——否则让给一个拿不出标题候选的 VC 框，用户什么都看不到；
  该死角在判定层消灭，面板如实告知「当前仍由本插件接管」。**1.2.4 起本条由「建议显示在」取代**，见上文。选「本插件优先」且词典联动本就关着时，
  面板不再渲染 VC 词典联动区（纯噪音，testplan Q24）
- **VC 框里的标题候选补齐与观感统一（Q25/Q26，1.0.32）**：VC 的 `jsonToWords` 把
  `value`/`displayed` 对调，去重谓词对 customDictionary 只比 `value` ⇒ **同名标题必被砍到
  只剩一条**；`disambiguateVcDisplayed` 只给冲突项加 `(文件名)` 后缀（区分形态按组统一，
  后缀只能在尾部——VC 首字母桶键取 `value.charAt(0)`）。词条加 `description = 路径` 作第二行
  小字。自动配置额外清空 VC 的 `displayedTextSuffix`（其默认值就是字面量 `" => ..."`，是
  **全局显示项**，确认框单列一条说明影响范围）。VC 侧图标按词条 type 的 CSS `::before` 决定、
  无 per-词典钩子，覆盖会误伤用户自己的词典 ⇒ 不覆盖，改把**本插件建议框对齐 VC 观感**
  （图标改书架语义、第二行 `0.75em`/`--text-muted`）
- **候选上限（1.1.0）**：VC 把全部来源混排后按显示文本长度升序取前 `maxNumberOfSuggestions` 条（默认 5），
  带 `(文件名)` 后缀的同名标题恰是最长候选、短查询下被挤掉；排序键由 VC 写死，本插件的补偿是自动配置时
  把该上限**只抬不降**到 10（testplan Q12 / Q25）

## 开 / 关两档 + 回车不接受（issue #10，Q49–Q58，已实现（1.2.5））

> 2026-10-23 立项。1.2.4 按信号收紧后报告者回复「问题依然在」：库里恰好有【项目】【json】这类标题（且只在
> 1–2 个文件出现、被链接过），按规则表就是会弹——规则本身没错，错在「不打任何符号也弹」这件事对一部分用户
> 就是打扰，阈值再怎么调都有普通词碰巧是标题名。套话过滤（≥ 3 个文件）1.2.4 已有，不再加码。
> 报告者不用补全插件、没有「打字出建议」的习惯；对这类用户最好的默认就是不弹（2026-10-24 用户定）。

- **设置**：「打字时建议标题链接」`headingLinkSuggestEnabled` 开 / 关，沿用 1.0.26 起的键名。
  - 开：即 1.2.4 现行规则（上文规则表 + 套话过滤），正文打字即弹，Tab / 点按接受；
  - 关：不建索引、不弹、VC 框里也不出本插件的标题（Q1 的零成本语义不变，Q55）；要链标题用原生 `[[##`。
  - 「建议显示在」（本插件的框 / VC 的框）只在**开着且装了 VC** 时显示，与上一行同级、不缩进（Q56）。
- **默认与迁移**（Q50）：**全新安装默认关**，保持 Obsidian 的默认行为（报告者原话：插件不应改软件的默认行为），用户在设置面板里自己开。**升级时统一改关一次**（2026-10-24 用户定）：1.2.4 及以前默认开，data.json 里存的 `true`
  分不清是默认还是自己打开的，只能一刀切；例外是开着 VC 联动（`manual` / `auto`）的保持原值，那是显式选择。只做一次，
  靠标记 `headingSuggestOffMigrated`（新装直接为 true），之后用户自己打开不会被改回。开发期评审构建写过的三档
  `headingSuggestTrigger` 先折算（只有 `auto` 算开）再走上面的规则，旧键删掉。
- **不做右键菜单开关**（Q61 撤销，2026-10-24 用户定）：评审构建做过编辑器右键菜单勾选项 + 「在右键菜单里显示开关」，
  没必要——默认关、设置面板里一个开关就够，不往菜单里加东西。评审构建存过的 `headingSuggestInEditorMenu` 加载时删掉。
- **回车不接受**（Q58）：框是打字时自己弹的，用户按回车的本意是换行。Obsidian 给 `PopoverSuggest` 内置了
  `Enter` 接受，且 `Scope` 按注册顺序取第一个匹配的处理器（对照 1.14.4 app.js 核过），追加同键处理器盖不住——构造时经
  公开的 `scope.unregister` 摘掉它（处理器列表 `keys` 未公开，认不出就不动）。**光摘掉还不够**（2026-10-24 真机抓出）：
  编辑器自己的 CM 键表里有 `{key: "Enter", run: () => editorSuggest.isShowingSuggestion()}`，有建议框开着就吞掉回车。所以再注册
  一个 Enter：先关框、返回 `undefined` 不拦截，按键落到编辑器时框已关，换行（列表续项）由 Obsidian 自己做。兜底：内置 Enter 没摘掉时 `selectSuggestion` 收到回车就关框、
  `exec("newlineAndIndent")`，不插链接。输入法组合中的回车归输入法（本来就不触发）。
- **否决：「打 `[[` 时」档**（评审构建做过，2026-10-24 撤销）：在 Obsidian 原生 `[[` 建议框的文件候选后追加标题。
  它要包原生框的 `suggestManager` / `renderSuggestion` / `selectSuggestion`，全是非公开结构，跟着 Obsidian 改版就会坏；
  而原生 `[[##` 本来就按子序列模糊匹配全库标题（打「交叉」能命中【1.1 交叉矩阵】），多出来的只是少打两个 `#`，
  还得补「高亮标题按 `#`」「完整命中提前」等一串与原生行为对齐的细节。用户定：开着多个捷径、关着不打扰，两档够了。
  先前提过的 `;;` 触发符同样否决：要用户额外记一个符号，违背「思维负载低」。

以及删除已生成的词典文件。词典**路径**的移除见上文「VC 侧同步收紧」。
