# 2.3 边界情况与设计决策

> 本表是**规格层**的边界决策；逐条**可操作 / 可断言**的测试场景（含"改配置后再触发"这类状态转移、
> 当前已知 bug 与其状态）见 [`doc/testplan.md`](../testplan.md)。改规格时回头核对 testplan 是否需同步。

| 场景 | 决策 |
|------|------|
| 文件中无 H2 及以上标题 | 插件不写入任何内容，文件保持不变 |
| 白名单标题有子标题 | **全部/部分匹配**：仅该标题本身跳过前缀、不占计数器槽位；其子标题会继续沿用**上一个已编号祖先**的计数（通常非预期，面板会 ⚠ 提示改用子树）。**子树匹配**：该标题及其下属所有子标题整体跳过前缀、均不占槽位 |
| 用户手动编辑了编号前缀 | 下一个防抖周期会将其覆盖为正确值；对前缀的手动编辑是预期行为。**修订预告（2026-07-10）**：[M11 的 CM6 原子区域](./5-Roadmap.md#milestone-11--信任包插队-m8a-之前)落地后此原则退役——编辑器内前缀只读（光标跳过、不可落点），编辑器外损伤仍由双哨兵自愈兜底（见 [附录 A](./A-方向审查与否决理由.md) §8.4） |
| 标题正文本身以数字起头（如手写 `## 2024 总结`） | **方案A（0.6.6）根治**：`stripPrefix` 只认带 Word Joiner 的（插件自己写的）前缀，`## 2024 总结` 无 WJ → `2024 总结` 整体是正文 → 首次即得 `## 1 ⁠2024 总结`，`2024` 完整保留、幂等（见 [2.4](./2.4-保留正文起头的数字.md)）。代价：手写的伪编号（`## 1. X`）不再被自动吸收，可用「清理非本插件的标题编号」命令主动清掉（见 [3.10](./3.10-清除编号.md)）|
| 在已编号文件上改模板的**前缀 / 后缀**字段后再触发 | 不叠加（**方案 A**，0.3.18）：剥离时前后缀接受「当前值 + 空串 + 全模板在用值并集」作候选，故「无前缀时编的号」与「旧前缀值」都能被剥净，再叠正确新前缀。候选只在其后紧跟序号 token 时才构成前缀，故 `第一印象`/`API 设计` 等不受误伤（见 testplan B2/B3）|
| 在**空行**上用快捷键直接转成标题（行内无文字） | 正常编号：空行转标题后形如 `### `，编号得 `### 1.1 `（标题文本为空，末尾即标题间隔符空格）。剥离器按**保留行尾空白**的原始文本匹配，故反复触发保持幂等、不会叠成 `1.1 1.1`（早期一处剥离 bug，已修复） |
| 标题间隔符填空格 / `. ` 等**含尾随空白**的值 | **所见即所得**：用户在间隔符输入框敲什么就用什么，写入文件与序列化都**原样保留**（`" "`→`1 标题`、`". "`→`1. 标题`）。GUI 实时预览也**如实显示尾随空格**（早期预览会 trim 末尾空白，把 `" "`/`". "` 显示成 `1标题`/`1.标题`，让人误以为空格没生效——已修复，仅曾失真于预览，实际编号一直正确） |
| 存在多个 H1 | **插件不改写任何 `#` 层级**。默认 `topLevel=H2` 时所有 H1 都不编号、原样保留，但每个 H1 仍是计数器**重置边界**——其后的 H2 重新从 1 起（多个 H1 = 多个顶层分节）。想给 H1 编号则把模板 `topLevel` 设为 H1（H1 → `1`/`2`/`3`）；想让某个 H1 作"标题"不编号则用白名单豁免（见 [3.4](./3.4-起始编号层级与多个H1.md)） |
| 标题层级跳跃（如 H3 → H5） | 缺失的中间层级如何呈现**由各模板自行配置**（占位策略 `skipFill`，见 [3.6](./3.6-模板系统.md)）：**补位**时保留一段并填入用户指定的占位字符（默认 `0` → `1.1.0.1`，也可填 `1` → `1.1.1.1` 或任意字符），使序号段数等于标题深度（H_n 有 n−1 段）；**不补位**时省略该段（H5 呈现为三段、与 H4 同形 `1.1.1`）；**不编号**（0.7.15）时跳级标题完全不编号、保持原样——面向「H5/H6 当样式性小标题」的用法，正常嵌套时照编（按上下文判定，testplan F7–F9）。无论哪种策略，缺失级计数器都不实例化（仍为 0、不被借号），随后首个真实的该级标题仍从 1 起算 |
| 白名单条目含首尾空格 / 行内格式 / 全角半角 / 大小写 | 比较前对标题与条目做同一套**归一化**（剥前缀 → 去行内 Markdown → NFKC → trim 并折叠空白 → 转小写），仅用于命中判定、不改写文件（见 [3.7](./3.7-白名单系统.md)） |
| 同一标题被多个白名单条目命中 | 取**豁免范围最大**者的并集：被任一条目命中即豁免；命中它的条目中只要有**子树**条目，则连同子树一并豁免 |
| 当前文件匹配多条路径规则 | 最具体的规则（文件路径 > 文件夹路径 > 全局默认）优先；并列时列表中靠后的规则胜出 |
| 无任何路径规则匹配当前文件 | 使用全局默认模板（`default.json`，面板显示为"默认"） |
| frontmatter 中 `obsidian-auto-headings` 值非 `true`/`false` | 视为非法，忽略该键，按缺省（跟随「全局自动编号」开关）处理；旧版 `ON`/`OFF` 文本及 `True`/`False` 大小写不符者均属非法（见 [3.2](./3.2-单文件开关.md)） |
| 「全局自动编号」关、但某文件 `frontmatter: true` | 该文件**仍自动编号**（文件级强制 opt-in）——`true` 覆盖全局开关。用于「全局沉默、个别文档常驻自动」（见 [3.2](./3.2-单文件开关.md)） |
| 手动「立即重新编号」命令遇到 `frontmatter: false` 或全局开关关 | **照常编号**——手动命令走独立路径，不看全局开关、不被 `false` 拦截（用户敲命令即明确意图），仅受「能否命中模板」约束（见 [3.1](./3.1-开关命令与生效判定.md)） |
| 当前文件无任何路径规则命中（含 `/` 根规则被删） | **无可用模板**：自动触发静默跳过（已有编号冻结不动）；手动命令弹 Notice「未匹配任何路径规则」。`frontmatter: true` 也不能凭空变出模板，同样静默跳过（见 [3.8](./3.8-按路径配置.md)） |
| 删除一个**正被路径规则引用**的模板 | 弹确认对话框，列出受影响规则并让用户选择去向：降级到「默认」（缺省）/ 改投他模板 / 连规则一并删（见 [3.6](./3.6-模板系统.md)） |
| 删模板 / 删路径规则后，已编号文件何去何从 | **不回滚**——配置层改动绝不批量扫库改文件；已写入的编号**冻结现状**，直到该文件下次被触发重排或被「清除编号」处理（见 [3.6](./3.6-模板系统.md)、[3.10](./3.10-清除编号.md)） |
| 想让某文件回到「无编号」裸标题 | 删模板 / 取消勾选（`false`）都不会清除已有编号；须主动用「清除当前文件编号」命令（或面板 [清除全库编号]），其剥离器用全样式并集、独立于模板（见 [3.10](./3.10-清除编号.md)） |
| 代码块内的 `#` 行 | 不视为标题，跳过处理 |
| 注释块内的 `#` 行（`%%…%%` / `<!--…-->`） | 不视为标题，跳过处理（M12，见 [3.17](./3.17-跳过区域.md)）——不编号、不推进计数器、不进 backlink 快照 |
| 开启 Obsidian「页内标题」（外观 → 页内标题，将文件名作为可编辑标题显示在正文中） | **无冲突**：页内标题是由文件名生成的**渲染层 widget**，不在 Markdown 源文本里；插件只读写源文本（`editor.getValue` + 行事务），既不会给它编号也不会因它错位。此时标题改由文件名承担，若想给正文 H1 章节编号，把模板 `topLevel` 设为 H1 即可（见 [3.4](./3.4-起始编号层级与多个H1.md)） |
