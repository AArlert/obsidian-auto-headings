# 3.18 固化编号并交还所有权（M12）

**动机**：M11/M12 的共同主题是用户信任度——让用户相信「用了这个插件，我的库不会被绑架」。
[3.10 清除编号](./3.10-清除编号.md)给的是「不要编号了」这条路；本节给的是另一条：**「我喜欢现在的编号，
但不想再被插件管着」**，以及「准备卸载，但要留住编号成果」。

**入口**：敏感操作 TAB 第 4 项 + 二次确认对话框。与「清除全库编号」一样**刻意不注册为命令面板命令**
——它比清库更需要防误触：清库清掉的编号还能重编回来，固化之后插件已认不出那些编号是自己写的。

**行为**：
1. 全库现有编号**原样保留**，成为普通文本。
2. 全库的 U+2060 一并移除——**必须是全文级剥离，不能只处理标题行**：`backlinks.ts` 的
   `displayAnchor` 刻意把 WJ 写进 `[[file#⁠1 ⁠标题]]`（Obsidian 锚点解析按字节比对、不剥 WJ），
   只剥标题行会让链接侧仍带 WJ、与标题字节对不上，**全库内链集体断链**。两侧同步归零才对。
   这也正是标记契约 §3 公布给下游的第一条配方（`/⁠/g`），语义一致。
3. `settings.retired = true`，插件**停止一切自动编号**。这道闸在 `shouldAutoTrigger` **首行**、
   **凌驾于 frontmatter `obsidian-auto-headings: true`**——只关 `autoNumber` 不够：带 `fm:true` 的
   文件本就绕开全局开关，固化后一编辑就会在已成普通文本的编号上再叠一层新前缀 → 双重编号。
   刻意**不动 `autoNumber`**（那是用户偏好，恢复接管时不该要他重设一遍）。
4. `headingSnapshots` 直接清空（插件已离场，改名表基线不再有意义），而非像清库那样刷新。

**离场状态必须可见**：`retired === true` 时全局设置 TAB 顶部显示提示条 + 「恢复接管」按钮。
离场后下面那个「全局自动编号」开关即便开着也不会有任何效果，没有这条提示用户只会觉得「插件坏了」
——这是本功能最容易砸掉信任的地方。

**恢复路径复用既有机制、不新建**：解除 retired 后编辑固化过的文件，那些编号因已无 WJ 而被
`hasUnclaimedForeignNumbering` 判为「外来编号」，`guardForeignNumbering` 命中并跳过自动写入
（每次「换到别的文件再回来」提示一次，机制见 testplan J13/J14）；用户跑既有的
「清理非本插件的标题编号」即可干净重编。

**对插件不可逆**：按契约「无 WJ ⇒ 插件从未碰过」，固化之后插件自己也再分辨不出那些编号的来源。
这是刻意的——正是「交还所有权」的字面含义。契约 §2 已就此加了例外说明。
