# Auto Headings 使用指南

[English](user-guide.md) | **简体中文**

[README](../README.zh.md) 背后的完整参考：每一项设置、每一个边界情况，以及插件到底往你的文件里写了什么。

## 开箱即用

下面这些是插件启用之后立刻就有的，你还没打开一次设置面板。

-   **零配置。** 装上、打开笔记、开始编辑，H2 及更深的标题立刻显示 `1` / `1.1` / `1.1.1` 编号——不用任何设置。新安装默认是「仅显示」模式，文件本身不被改动（见[两种模式](#两种模式仅显示与写入文件)）。
-   **你的标题层级神圣不可侵犯。** 插件只增删编号前缀，**绝不**改写 `#`/`##`/`###`。一个文件里有多个顶级 `# H1` 时插件不动它们，只把每个 H1 当作分节边界（其下编号各自重新开始）。
-   **不跟你抢打字节奏。** 重新编号在你停止输入后按防抖延迟触发（50–2000 ms，可调），并以**一次编辑器事务**重写整个文件——一次 `Ctrl/Cmd+Z` 即可撤销，光标位置也保持不动。
-   **编号没有后台开销。** 编号**只**处理你正在编辑的那一个文件——由编辑、手动命令、或设置面板改配置后对活动文件重排三种时机触发，**从不**为"用了某模板的所有文件"扫描全库。没打开的文件只会被你**显式确认的批量操作**触碰（路径规则的批量重编号、切换模式时的清除 / 写入、清除全库编号）。唯一会读全库的是「标题链接建议」：启用时在本地读一遍全库标题建索引（上限 5 万条），之后只做增量更新；不需要可以在全局设置里关掉。插件不联网、不收集任何数据。
-   **两层独立开关，外加一个手动兜底。** 启用插件不等于让它在整个库里随便动手：一个全局的自动编号开关决定编辑笔记是否会触发重新编号。在笔记 frontmatter 里加 `obsidian-auto-headings: true` 或 `false`，可以针对这一个文件覆盖该开关——让它在全局关闭时单独常驻开启，或者让它在全局开启时对某个文件完全免打扰。**立即重新编号**命令把这两层都绕开：你主动敲了命令，意图已经足够明确，直接跳过一切开关立刻编号。
-   **配置只住在设置里，不住在你的笔记里。** 模板、路径规则、白名单全部在设置面板里管理——除了上面那一个可选的开关键，frontmatter 里不会被写入任何东西。打开一篇笔记，看不出插件装没装。
-   **开箱即双语。** 整个界面自动跟随 Obsidian 自身的语言设置（中文 / 英文），也可以手动锁定某一种。移动端完全可用（`isDesktopOnly: false`）。
-   **打出来，就链接上。** 在任意笔记正文里打字时，Auto Headings 会建议库中与你输入匹配的标题——按 `Tab`（移动端点按）即可把这段文字自动补全为该标题的完整名称，并变成指向它的可点击链接。同样默认开启，已编号的标题也能正确链接。

### 快速上手

1. 安装并启用插件（见 [README](../README.zh.md#安装)）。
2. 打开任意笔记开始编辑——H2 及更深的标题自动获得编号。
3. 想再深入定制，打开 **设置 → Auto Headings**：
    - **全局设置**：语言、全局自动编号开关、防抖延迟、在大纲中显示编号、Backlink 同步、标题链接建议。
    - **路径与模板**：路径规则表（每条规则选模板和模式：写入文件 / 仅显示）+ 模板编辑器（实时预览、白名单）。
    - **敏感操作**：三个清除入口。
4. 按文件覆盖：frontmatter 写 `obsidian-auto-headings: true/false` 可强制开 / 关单个文件；「立即重新编号」命令绕过一切开关。

## 两种模式：仅显示与写入文件

每条路径规则都有一个「模式」（**设置 → 路径与模板 → 路径规则**的「模式」列）。两种模式用同一套模板、白名单和跳级规则，算出来的编号完全一样，区别只在编号放在哪：

|                                          | 仅显示                           | 写入文件                     |
| ---------------------------------------- | -------------------------------- | ---------------------------- |
| 笔记文件                                 | 一个字都不改                     | 编号作为真文字写进标题       |
| 实时预览、阅读视图、嵌入、悬浮预览       | 显示编号                         | 显示编号                     |
| Obsidian 内置「导出为 PDF」              | 带编号                           | 带编号                       |
| 源码模式                                 | 只显示原文                       | 编号就是原文的一部分         |
| Obsidian 自带的大纲面板                  | 显示编号（可在设置里关掉）       | 看得到                       |
| 文件内搜索                               | 看不到编号                       | 看得到                       |
| GitHub、Obsidian Publish、外部编辑器     | 看不到编号                       | 看得到                       |
| 改标题后链接跟着更新                     | 支持                             | 支持                         |

-   **默认值**：新安装时根规则 `/` 是「仅显示」，之后新加的规则默认跟随根规则。从旧版本升级的库保持「写入文件」，行为与升级前一样。
-   **按文件夹混用**：比如 `/` 仅显示、`论文/` 写入文件。更具体的规则优先，与模板的解析规则一致。
-   **切换**：在某条规则上改模式、删掉规则、改路径、把模板改成「不编号」，只要有笔记会因此换模式，插件会先弹一个确认框，列出受影响的笔记数：
    -   写入 → 仅显示：可以选择「清除本插件写入的编号」（默认勾选）。只去掉插件写的编号，你手写的编号不动；标题文字变了，指向它们的链接会一起更新。不勾就保留现有编号。
    -   仅显示 → 写入：可以选择「立即写入编号」；不勾就等下次编辑时再写（已打开的笔记会马上更新）。
    -   点取消，规则保持不变。
-   **残留的旧编号**：仅显示的笔记里如果还留着插件以前写入的编号（比如不勾清除，或者把写入文件夹里的笔记挪了过来），插件会盖住旧编号、只显示一层新编号，并给新编号加一条虚线；鼠标停上去有说明。旧编号仍在文件里，导出到别处会看到它。命令「清除本文件残留的插件编号」可以清掉，这条命令只在仅显示的笔记里出现。
-   **手写编号**：一篇仅显示的笔记里如果超过一半的标题已经带着手写或导入的编号（比如从别的编号插件迁过来），插件不显示编号，免得出现两套数字，并在打开时弹提示，点开可以预览并清理手写编号。个别以数字开头的标题（如「2024 总结」）不受影响，照常编号。
-   **大纲面板**：仅显示的编号也会出现在 Obsidian 自带的大纲面板里，搜索过滤、折叠、拖动小节后照样对得上；带残留旧编号的标题在大纲里只显示文件原文。不想要可以在**设置 → 全局设置 →「在大纲中显示编号」**关掉。
-   **「立即重新编号」**在仅显示的笔记里只刷新显示，不写文件。
-   **固化编号并交还所有权**：仅显示的编号本来就不在文件里，固化后会随插件一起消失。想把它们留成文字，先把规则切到「写入文件」并选择立即写入，再固化。

## 深入定制

默认行为不够用时，这些是你会用到的。

### 随便改标题，链接自动跟

大多数编号插件只更新数字，标题文字变了引用却不跟。本插件两者都同步。

```
<!-- note.md，改动前 -->
## 1 Foo

<!-- other.md -->
详见 [[note#Foo]]。
也可用 Markdown 链接写作 [同一节](note.md#Foo)。
```

你改了标题——不只是数字，连文字一起改：

```
<!-- note.md，改动后 -->
## 2 Foobar
```

引用在同一次编辑里自动跟着变：

```
<!-- other.md -->
详见 [[note#Foobar]]。
Markdown 链接同步变成 [同一节](note.md#Foobar)。
```

不用手动全库查找替换，锚点不断。这套做法承袭自 Header Enhancer——目前唯一解决这个痛点的插件——并在其基础上做了几处针对性改进：原子写入（避免改写中途被打断导致文件半损坏）、更稳妥地处理重复标题，等等。（少数边界情况——重复标题、块引用、多级锚点——出于安全考虑不处理，见[说明](#说明)。）

默认开启，首次实际改写链接时会弹一次说明性提示。如果你想自己管理链接，也可以在**设置 → 全局设置**里关掉。

### 完全可定制的模板

每一级标题（H1–H6）都能独立设置：

-   **前缀**与**后缀**（如"第"+"章"→`第1章`）
-   **序号样式**——七种：阿拉伯数字（`1`）、中文数字（一二三）、带圈数字（①②③）、大小写字母、大小写罗马数字
-   **序号间隔符**（`1.1` 中的 `.`）与**标题间隔符**（数字与标题文字之间的空格）
-   **继承前级**开关——默认开启（`1.1.1`）；关闭某一级后该级只显示自己的序号（如 `a)` 而非 `1.a)`）
-   **继承级数**——继承前级不再是全有或全无。默认继承到起始层级，也可限定"最多往上带几级"：H1 独立成"一、二、"、H2 另开一套 `1`、H3 只带上它的 H2 父级得 `2.1`，而不必把 H1 拖进前缀。此前想要这种中间态只能调深起始层级，代价是连带取消 H1 的编号
-   **祖先序号渲染**——解决的是两种排版惯例之间一个真实的冲突。提纲式希望每个祖先段被嵌进更深前缀里时仍保留**自身**的序号字形（`1.a.①`）；中文书式恰恰相反——章节标题本身要显示"一"，但它一旦作为祖先段出现在更深的节号里就该降级为阿拉伯数字（H2 显示"一"，到 H3 变成 `1.1`）。单一的序号字段没法同时满足这两个方向，所以 `ancestorNumeral` 只控制祖先段，与本级自身怎么呈现互不影响。

以上所有设置都会实时预览，写入文件前就能看到确切的编号格式。可以新建任意多个具名模板（在设置面板里改名、编辑或删除）。

### 一个文件夹一个模板——甚至一个文件一个模板

路径规则表把文件夹和单个文件映射到具名模板，**最具体的规则优先**（文件级规则会覆盖它所在文件夹的规则）。`/papers` 用学术编号，`/book` 用章节样式，其余地方用默认的 `1 / 1.1`——同一个库里互不干扰，无需手动切换。规则表支持拖拽排序、根据库里真实路径自动补全（可逐层浏览文件夹，也可打字模糊搜索），并在"全局自动编号开着却没设根规则 `/`"时提醒你。

规则级还有两件配套工具：模板下拉里选伪模板**「不编号」**，即可整个文件夹关闭编号（不用再逐文件写 frontmatter 开关——已有编号会冻结保留、不会被剥除）；每行的**批量重编号**按钮可在一次确认后对该规则命中的全部文件重新编号（每个文件用它自己生效的模板；frontmatter 已关闭或含外来编号的文件会被跳过）。

### 白名单——把结构性标题排除在计数之外

"目录""附录""参考文献"这类标题不该有编号，也不该占用计数器的槽位。白名单（按模板配置）用三种匹配方式处理：

-   **全部匹配**——标题文字与条目完全相同
-   **部分匹配**——标题文字包含该条目
-   **子树匹配**——命中的标题**及其下所有子标题**整体作为一个块被豁免；这个块结束后编号重新开始（很适合"附录不该打乱后面章节的计数"这种场景）

子树块结束后编号**重新开始**、而不是接着块前的数继续算，这是默认行为，不需要你另外找开关去打开——对学术与技术引用规范（APA、Chicago、IEEE、RFC、GB/T 7714）的调研发现，约 85% 的规范都在附录一类的块之后断开编号、其后重新起算。

默认模板已经预填充了常见的结构性词条，中英文都有（目录、附录、附图、附表、参考文献、致谢、摘要、索引及对应英文）。

编辑器本身也是为**快速调整**而设计的，不只是一个平铺列表：

-   **点击已有条目的文字即可原地编辑**——不用先删除再重新添加
-   匹配方式是行内的**分段控件**（`=` 全部 / `≈` 部分 / `▸` 子树）——单击切换，双语 tooltip 说明每个图标的含义
-   每条都有**命中数角标**，显示它在当前打开文件里豁免了多少个标题，悬停可看具体是哪些
-   当"全部/部分匹配"条目命中的标题**含子标题**时会出现**⚠ 警告图标**——提示你也许该换成子树匹配
-   **搜索框 + 排序下拉**（按添加顺序 / A–Z / 匹配方式）让长白名单也好管理
-   面板底部的实时预览会精确显示当前文件里哪些标题正在被豁免

白名单是**按标题文字**匹配的，管的是"这一类词"。如果你要的是"**就这一篇里的这一行**不编号"——比如
某篇笔记里的「临时讨论」不该有编号，但同名标题在别的笔记里是正常章节——在那行标题的**末尾**加上
`<!-- skip -->` 即可：

```
## 临时讨论 <!-- skip -->
```

它在阅读视图里不可见；被跳过的标题**不占计数器槽位**，后面的标题编号照常连续。给一个已经有编号的
标题补上这个标记，下次重排会把那个编号摘掉。目前只作用于标记所在的那一行，不含它下面的子标题。

> 这是给"偶尔有这么一行"准备的兜底写法，不是日常用法——把整类词排除请用白名单。后续版本会在标题旁
> 提供一键切换，不必再手写。

### 清除命令：需要清空重来时

-   **立即重新编号**——立刻强制重编当前文件（见[开箱即用](#开箱即用)——这会绕过一切开关）
-   **清除当前文件编号**——剥掉本插件曾经写过（或可能写过）的全部编号前缀，还原为裸标题。它**同时暂停这一个文件**（往 frontmatter 写 `obsidian-auto-headings: false`），否则你下一次按键就会把编号编回来；想重新交给插件管，跑一次「立即重新编号」即可，它会顺手把那条属性去掉
-   **清理非本插件的标题编号**——只剥离**不是**本插件写的编号（手写的 `1.` 前缀、导入文档自带的编号等），本插件自己写的编号保持不动——用于接管你不是从零开始写的文档
-   **清除全库编号**——设置面板里的一个按钮，刻意**不做成命令**（避免被快捷键或命令面板误触发），需要二次确认，且收纳在默认折叠的"危险区域"里

## 工作原理——以及一件你应该知道的事

> 本节只适用于**写入文件**模式。仅显示模式不往文件里写任何字符。

为了把自己写的编号与你的正文区分开，插件在每个编号前缀末尾写入一个不可见的 **Word Joiner** 字符（U+2060）：`## 1 ⁠我的标题`。这正是安全性的来源——只是*看起来*像编号的正文（`2024 年度总结`、`API 设计`）不会被误当旧编号吃掉。

用不可见 Unicode 字符标记前缀这个思路，最初来自 gurjar1/auto-heading-obsidian。本插件在此之上又加了一层保险：自 0.7.20 起，哨兵字符不再只放在前缀末尾，而是**首尾各放一个**。如果你在编辑时（比如改后缀）不小心把尾部那个删掉了，行首那个依然存活，成为"这里确实有插件前缀"的证据——于是下一次重新编号能把这一行**自愈**回正确状态，而不是要么把序号叠加重复、要么瞎猜误伤你的正文。

对你的影响：

-   该字符不可见，不影响排版、导出与阅读。
-   复制 / 导出的文本会带着它；若用 `grep` 精确检索标题文本，注意它位于序号与标题之间——把 `"1 我的标题"` 当成一整段连续字符串去搜是搜不到的。
-   **Dataview**：它能碰到标题文本的入口有三个——`TASK` / `LIST` 查询的 `section`、链接的 subpath、以及 DataviewJS 里的元数据缓存，这三处读到的都含这个字符。最省事的办法是**别再用精确匹配**：编号永远是前缀，所以 `endswith(section.subpath, "我的标题")` 不需要任何转义就能用。归一化配方（以及一处更正：Dataview **没有** `file.headers` 字段，早期 README 的说法是错的）见[标记字符契约](marker-contract.md#dataview)。
-   **粘贴到其他应用**（微信、知乎、Notion、邮件客户端等）：**复制净化**恒开、无需配置——复制 / 剪切时插件自动把这个字符从剪贴板剥净，外部应用收到的就是干净文本；同一会话内原样粘贴回本库时自动还原，编号照常重排、不会出现双重编号。（1.0.10 起提供、默认开；1.0.16 起取消开关——不往你的剪贴板里塞隐形字符是本插件的固有承诺，不是可选项。）净化只覆盖交互式复制 / 剪切；若从别的渠道拿到了带该字符的文本，可在目标应用手动 `.replace(/\u2060/g, "")` 清理。
-   若手动删编号残留了零散字符，「清除当前文件编号」/「清理非本插件编号」命令可一键清理。
-   **与同类插件共存**：gurjar1/auto-heading-obsidian 等插件同样用 U+2060 做标记，与本插件**不能同时启用**——双方会互相把对方的编号认作自己的。
-   **给下游开发者**：标记字符的完整字节格式、稳定性承诺与互操作代码片段，见[标记字符契约](marker-contract.md)（英文）。

## 导出与外发

编号是真文本，会跟着你的文档走。各出口的现状与建议：

-   **复制到其他应用**：已消除——「复制净化」恒开（1.0.16 起无开关），交互式复制 / 剪切的出口不再携带不可见字符（见上节剪贴板说明）。
-   **Pandoc**：编号已经烧入正文，别再让 Pandoc 编一遍——带 `--number-sections` 导出会得到 `1.1 1.1 引言` 式的双重编号。把现成的 [`assets/pandoc/strip-autoheadings.lua`](../assets/pandoc/strip-autoheadings.lua) 挂进导出管线即可：默认模式剥掉插件前缀，让 `--number-sections` 编出单层干净编号；加 `-M autoheadings=strip-marker` 则保留插件编号、只去掉那个不可见字符。两种模式下标题里的**粗体**、`代码`、链接等内联格式都完好。已对 pandoc 3.10 实测。
-   **Pandoc 出 PDF**：用 `--pdf-engine=typst` 导出，**PDF 文本层里查不到任何 U+2060**——即便不挂 filter，这个字符也在到达页面前就被丢弃了，PDF 里的复制与搜索一切正常。其他 PDF 引擎未测。
-   **Obsidian 内置「导出为 PDF」**：仅显示模式下导出的 PDF 带编号（1.2.0 实测）。写入模式下编号会进 PDF，但那个不可见字符在 PDF 文本层里的表现仍未验证，上面 Pandoc 的结论**不能外推**。
-   **Obsidian Publish**：仍未验证。仅显示模式的编号不会出现在 Publish 上（Publish 不运行本插件）。
-   想要"编号只在 Obsidian 里可见、文件保持零改动"？用[仅显示模式](#两种模式仅显示与写入文件)。

## 从 Number Headings 迁移

Number Headings 已长期停止维护（约 2.5 年无更新）。迁移到本插件只需三步：

1. 禁用 Number Headings；
2. 启用本插件并配好模板（开箱默认 `1.1.1`，与其风格接近；也可用路径规则给不同文件夹配不同模板）；
3. 对旧文件跑一次**清理非本插件的标题编号**——它只剥不是本插件写的编号（Number Headings 的、手写的、导入文档自带的都算），随后正常编辑即可按你的模板重新编号。

它 issue 区久拖未决的两条呼声，本插件**都已实现**：按文件夹排除编号（路径规则里选「不编号」伪模板）、跳过注释块内的标题（`%%…%%` 与 `<!-- -->` 内的标题不编号，也不占计数器槽位）。

## 说明

-   **语言**：插件界面自动跟随 Obsidian 语言（中 / 英），也可在设置中锁定。本指南有[英文版](user-guide.md)。
-   **Backlink 同步的边界**：支持 Wikilink 与行内 Markdown link/image（Markdown fragment 写回时采用 URL 编码）。为避免误改，以下情况保守跳过——重复标题、块引用（`^id`）、多级锚点（`#A#B`）、外部 URL，以及行内 / fenced code 中长得像 Markdown 链接的文本。开启同步不会回溯修复开启之前就已断的链接。也可在**设置 → 全局设置**中关闭。
-   **撤销**：单文件改写是一次编辑器事务，一次 `Ctrl/Cmd+Z` 即可撤销；对*其他*文件的 Backlink 改动不在该事务内。「清除全库」**不在**撤销历史内，请先备份。
-   **移动端**：支持（`isDesktopOnly: false`）。

## 如何干净地离开

只用过仅显示模式的话，插件从没改过你的文件，直接卸载即可。

写入模式下，插件写进文件的只有编号前缀和两个不可见标记字符，全部可以彻底移除。按「要不要留住编号」分两条路：

**不要编号了** —— 设置 → 敏感操作 → **清除全库编号**（会先自动关闭全局自动编号，避免边清边被编回去），标题还原为裸标题。

**要留住编号** —— 设置 → 敏感操作 → **固化编号并交还所有权（全库）**。现有编号原样保留、变成普通文本，只移除那两个不可见标记，此后插件停止一切自动编号。适合「喜欢现在的编号，但不想再被插件管着」或「准备卸载但要留住编号成果」。标记是全库移除的，**包括写在内部链接锚点里的**，所以 `[[笔记#标题]]` 仍能正常解析。固化之后插件自己也认不出这些编号是它写的——这正是「交还所有权」的含义，但也意味着这一步是单向的：想让它重新接管，需先跑一次**清理非本插件的标题编号**，否则现有编号会被再叠一层新前缀。

然后：

1. 禁用 / 卸载插件；
2. （可选）删除 frontmatter 里的 `obsidian-auto-headings` 键——没有插件时它是惰性的。

标记字符一直活在文件字节里，所以就算卸载多年后想清理，重装插件跑一次「清除全库编号」仍能把当年的编号精确剥净；不便重装时的外部批量方案（一行命令）见[标记字符契约](marker-contract.md)。
