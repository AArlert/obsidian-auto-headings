## Fix nested code-fence numbering reset / 修复嵌套代码块导致的编号重置

**English**

Bug fix release for [issue #9](https://github.com/AArlert/obsidian-auto-headings/issues/9).

- Fixed: when a fenced code block was nested inside another fence with a *shorter* delimiter run (e.g. an outer block opened with four backticks containing an inner block delimited by three backticks), the shorter inner fence was incorrectly treated as closing the outer one. Any `#`-prefixed line inside the wrongly-reopened region (such as a YAML comment) was then misread as a real heading, which reset the numbering counters for every heading level below it.
- The fence scanner now follows CommonMark's actual closing rule: a closing fence must use the same delimiter character *and* be at least as long as the opening fence. A shorter same-character run no longer closes the block — it's just ordinary content inside it.
- No changes to any other behavior; existing numbering, backlink sync, and comment-block handling are unaffected.

**中文**

修复版本，对应 [issue #9](https://github.com/AArlert/obsidian-auto-headings/issues/9)。

- 修复：当一个围栏代码块嵌套在另一个**定界符更短**的围栏内部时（例如外层用 4 个反引号开启，内部又出现一段用 3 个反引号定界的代码块），插件会错误地把内层较短的围栏当成外层的闭合标记。该「误闭合」区域内任何以 `#` 开头的行（比如 YAML 注释）就会被当成真正的标题，进而把它下方所有标题的编号计数器错误清零。
- 围栏扫描逻辑现在遵循 CommonMark 的真实闭合规则：闭合行必须使用**同种定界符**、且**数量不少于**开启行，数量不足的同符号行不再闭合围栏，只是块内的普通内容。
- 不涉及其他行为变化，现有编号、Backlink 同步、注释块处理均不受影响。
