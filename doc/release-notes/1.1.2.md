## Markdown heading links now stay in sync / Markdown 标题链接现在也会同步

**English**

Backlink sync now covers Obsidian's inline Markdown-link syntax in addition to Wikilinks. When a heading is numbered or renamed, references such as `[Details](note.md#Heading)` and `![Embed](note.md#Heading)` receive the new fragment in the same sync pass.

- Same-file, cross-file, relative-path, URL-encoded, angle-bracket destination, optional-title, and image/embed forms are supported.
- Only the destination fragment changes. Labels, paths, optional titles, and the leading `!` remain byte-for-byte intact; new fragments are URL-encoded.
- External URLs, plain file links, block references, multi-level fragments, malformed URL encoding, escaped links, inline code, and fenced code are left untouched.
- Existing Wikilink behavior and the combined update count are unchanged.

This remains a change-triggered safety feature, not a historical broken-link scanner: links that were already stale before a heading changes are not guessed or rewritten retroactively.

**中文**

Backlink 同步现在除了 Wikilink，也覆盖 Obsidian 的行内 Markdown 链接语法。标题被编号或改名后，`[说明](笔记.md#标题)` 与 `![嵌入](笔记.md#标题)` 会在同一轮同步里获得新的 fragment。

- 支持同文件、跨文件、相对路径、URL 编码、angle-bracket destination、可选 title 与 image/embed 形态。
- 只改 destination 的 fragment；label、路径、可选 title 与前导 `!` 原字节保留，新 fragment 统一 URL 编码。
- 外部 URL、纯文件链接、块引用、多级 fragment、坏 URL 编码、转义链接、行内代码与 fenced code 保守不动。
- 既有 Wikilink 行为与统一更新计数保持不变。

它仍是由标题变化触发的安全同步，不是历史断链扫描器：标题变化前就已经陈旧的链接不会被猜测或追溯改写。
