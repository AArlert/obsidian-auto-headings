## Fix: a heading you just typed now gets numbered right away / 修复：刚敲出来的标题现在会立刻编号

**English**

A bug fix for the most basic thing the plugin does.

- **Typing a new heading and moving on now numbers it immediately.** Previously, if you typed `## Some title` and then moved the cursor straight to another line, the number simply never appeared — you had to make one more edit (pressing Enter was the usual accident that fixed it) before the plugin caught up. The same stall could happen after changing a heading's level with `#`.

  The cause was a guard that froze the entire line your cursor was on. It was there for a good reason — to stop a trailing space you had just typed from being swallowed — but freezing the whole line also withheld the number, and the condition for un-freezing it ("once you move away") never actually fired: moving the cursor isn't an edit, so nothing woke the plugin up.

  That guard is gone. Now only the trailing space itself is preserved, and numbering is written in the same cycle regardless of where your cursor is. Nothing about the original trailing-space fix is lost: the space you just typed still survives, and it is tidied up as before once you move on.

- **Numbering writes are now surgical.** Instead of rewriting the whole heading line, the plugin now replaces only the characters that actually changed. Since the number goes at the start of the line and your cursor is usually at the end, the two no longer overlap — so writing a number while you are still typing can't nudge your cursor or disturb a selection.

**中文**

修一个影响插件最基本行为的 bug。

- **敲完新标题直接把光标移走，现在会立刻编号。** 此前你敲下 `## 某个标题` 然后光标直接切到另一行，编号根本不会出现——必须再编辑一次（多数人是碰巧按了 Enter 才发现好了）插件才补上。用 `#` 改标题层级后也会卡住同样一下。

  根因是一道「冻结光标所在整行」的守卫。它本身是有道理的——防止你刚敲下的行尾空格被静默吃掉——但冻结整行连编号也一并扣住了，而解除冻结的条件（「等你把光标移开」）实际上从不成立：**移动光标不是一次编辑**，插件根本不会被唤醒。

  这道守卫已经拿掉。现在只保住行尾空格本身，编号则不论光标在哪都照常在当轮写入。原来那个修复一点没丢：你刚敲的空格依然保得住，等你移开后也照旧被清理干净。

- **编号写回改为精准改写。** 插件不再重写整行标题，而是只替换真正变化的那几个字符。编号加在行首、你的光标通常在行尾，两者不再重叠——所以哪怕在你还在打字时写入编号，也不会挪动你的光标或打乱选区。
