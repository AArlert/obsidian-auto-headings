## Three ways the plugin stopped overruling you / 三处「你已经表态了，插件还自作主张」

**English**

- **"Clear numbering in current file" actually works now.** It used to be decorative: the command cancelled the one pending debounce timer, then your next keystroke renumbered the file right back. With global auto-numbering on, it could never produce a lasting effect — you saw "Numbering cleared" and watched the numbers return seconds later. Clearing now also **pauses that file** by writing `obsidian-auto-headings: false`, folded into the *same* editor transaction so one undo reverts everything. Run **Renumber now** to hand the file back — it removes the property, making clear ↔ renumber a symmetric pair. If the file wasn't going to be auto-renumbered anyway (global toggle off, or a "no numbering" path rule), nothing is written to your frontmatter.
- **The plugin no longer fights you for the keyboard.** Type a space at the end of a heading, pause longer than the debounce, and that space used to vanish — heading text gets its trailing whitespace normalised, which is required for idempotence but has no business happening mid-keystroke. The automatic path now leaves **the line your cursor is on** alone and renumbers everything else; that line is picked up on the next trigger after you move away. Manual commands still rewrite the whole file.
- **Fixed: a stray trailing space could silently disable numbering for a whole file.** The migration guard compared "text with numbering stripped" against the raw text — but the stripper also normalises trailing whitespace, so `## Heading ` (no numbering anywhere in the file) looked like foreign numbering. The result: numbering silently skipped for that file, plus a misleading "run Clean foreign numbering first" notice. Found while writing tests for the item above.
- **Note on `obsidian-auto-headings: false`:** it now means "don't auto-**number** this file" rather than "ignore this file entirely" — heading-rename backlink sync keeps running. That capability is global and orthogonal to numbering, and since clearing numbering now writes this property, letting it also stop rename-safety would trade away the plugin's headline feature for a numbering cleanup. To silence the plugin completely for a file, turn off the **Update backlinks** master switch.

**中文**

- **「清除当前文件编号」不再是摆设。** 它此前只取消了当前那一个待处理的防抖计时器，你下一次按键就把编号编了回去——只要「全局自动编号」开着，这条命令**永远不可能产生持久效果**：提示说「已清除编号」，几秒后编号回来了。现在清除会**同时暂停这一个文件**（写入 `obsidian-auto-headings: false`），并**并入同一次编辑器事务**，一次撤销即整体回退。想重新交给插件管，跑一次**「立即重新编号」**——它会顺手移除那条属性，使「清除↔重新编号」成为对称的一对。若该文件本来就不会被自动重编号（全局开关关，或路径规则为「不编号」），则一个字都不会往你的 frontmatter 里写。
- **插件不再跟你抢键盘。** 在标题末尾敲一个空格、停顿超过防抖时长，那个空格此前会被静默吃掉——标题文本的行尾空白会被归一化，这是幂等所必需的，但不该发生在你打字打到一半的时候。自动路径现在**放过光标所在的那一行**、其余行照常重排；等你把光标移开，下一次触发再补上。手动命令仍然整文重排。
- **修复：一个行尾空格就能让整个文件的编号静默失效。** 迁移守卫拿「剥掉编号后的文本」与原文直接比较，而那个剥离器末尾也会归一化行尾空白，于是 `## 标题 `（全文一个编号都没有）被判成了外来编号。后果是该文件的自动编号被整个跳过，还弹出一句误导性的「请先执行『清理非本插件的标题编号』」。这个缺陷是在给上一条写测试用例时撞出来的。
- **关于 `obsidian-auto-headings: false`：** 它的含义收窄为「不自动**编号**这个文件」，而非「完全无视这个文件」——标题改名的内链同步照常进行。链接同步是全局能力、与编号正交；而既然「清除编号」现在会写入这条属性，若让它连改名不断链也一并停掉，等于用一次编号清理换掉了插件的招牌功能。要让插件对某个文件彻底静默，请关闭**「更新反向链接」**总开关。

---

**Upgrade note / 升级说明**

Nothing in your files changes on upgrade. The frontmatter property is only ever written when *you* run "Clear numbering in current file", and only when that file would otherwise be renumbered immediately.

升级本身不改动你的任何文件。那条 frontmatter 属性只在**你主动**跑「清除当前文件编号」时才会写入，且仅限于该文件确实会被立刻重编号的情况。
