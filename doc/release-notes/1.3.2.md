> **1.3.2** makes hand-written numbering handling safer and smarter: the plugin now tells "sure" from "unsure" and never silently deletes the unsure ones, it recognizes more ways of writing numbers, "Display only" mode no longer stacks its numbers on top of yours, and "Clear vault numbering" only removes numbers the plugin wrote.
>
> **1.3.2** 让手写编号的处理更稳、更准：插件现在分得清「拿得准」和「拿不准」，拿不准的绝不悄悄删字；能认出更多编号写法；「仅显示」模式不再把自己的编号叠在你的编号上；「清除全库编号」只清插件自己写的编号。

## What's new / 更新内容

**English**

**Sure vs. unsure hand-written numbering**

- The plugin now looks at the whole note, not each heading alone. Headings that count up from 1, child numbers that continue their parent's (`4` → `4.1`), and explicit forms like `1.`, `一、`, `(1)`, `①`, `第三章` are **sure**.
- Headings like `2024 review`, `30-second pitch`, `6 key points` or an isolated `1.2 release` are **unsure**. The cleanup commands leave them alone and tell you how many they skipped; click **Review…** to tick them yourself. In the preview dialog they start unchecked.
- A note with only unsure headings no longer blocks automatic numbering.
- "Clear numbering in current note" no longer deletes the first word of headings like `vim config`, `XML parsing` or `C language`.

**More ways of writing numbers**

- `第一部分` / `第二部分`, `第1步` / `第2步`, and `Step 1`, `Chapter 2`, `Part II`, `Appendix A`, `§1` are now recognized, and the cleanup removes the whole lead-in (`Step 1 Install` → `Install`). A single `Part 2 of …` in normal text is only "unsure".
- Headings that would end up with the same name after cleanup (`Week 1 plan` / `Week 2 plan`) are no longer marked sure, so the cleanup can't turn them into two identical `plan` headings.

**"Display only" mode and hand-written numbering**

- Notes where a whole heading level is numbered by hand (for example every `##` is `一、`, `二、`, `三、` with plain `###` below) no longer get the plugin's numbers stacked on top (`1 一、Background`). Numbers are hidden for that note and a notice offers to review and clean up. A note with just one or two hand-numbered headings still shows numbers as usual.

**"Clear vault numbering" keeps your own numbering**

- **Settings → Maintenance → Clear vault numbering…** now removes only numbering this plugin wrote. Numbering you typed yourself is left byte-for-byte; the result notice says how many files have some and points you to **Clean up handwritten numbering…** in that note's menu, which shows a preview first. Before, it also removed hand-written numbering across the whole vault, which cannot be undone for files that aren't open.

**中文**

**手写编号分「拿得准」和「拿不准」**

- 插件现在看整篇笔记，而不是一个标题一个标题地猜。同一层从 1 起连续递增的、子标题编号接得上父标题的（`4` → `4.1`）、带着 `1.`、`一、`、`（一）`、`①`、`第三章` 这类明确写法的，算**拿得准**。
- `2024 总结`、`30 秒版`、`6 个要点`、孤立的 `1.2 版本发布` 这类算**拿不准**：清理命令不动它们，提示里告诉你跳过了几处，点「检查…」可以自己勾；预览框里默认不勾。
- 只有拿不准标题的笔记，不再因此暂停自动编号。
- 「清除当前文件编号」不再把 `vim 配置`、`XML 解析`、`C 语言` 这类标题的第一个词删掉。

**认得更多编号写法**

- `第一部分` / `第二部分`、`第1步` / `第2步`，以及 `Step 1`、`Chapter 2`、`Part II`、`Appendix A`、`§1` 现在都能认出来，清理时连前面的词一起去掉（`Step 1 安装` → `安装`）。正文里单独出现的 `Part 2 of …` 只算拿不准。
- 清理后会变成同名的标题（`Week 1 计划` / `Week 2 计划`）不再算拿得准，清理不会把它们剥成两个同名的 `计划`。

**「仅显示」模式遇到手写编号**

- 某一级标题整级都是手写编号的笔记（比如每个 `##` 都是 `一、`、`二、`、`三、`，下面挂着不带编号的 `###`），不再被插件叠上编号（`1 一、背景`）：这篇不显示编号，并提示你查看和清理。只有一两处手写编号的笔记照常显示编号。

**「清除全库编号」保留你自己的编号**

- **设置 → 编号维护 → 清除全库编号…** 现在只清插件自己写的编号，你手写的编号一个字都不动。结果提示会写出有几篇带手写编号，并指向该笔记本篇菜单里的「清理手写编号…」（先预览再清理）。以前它会把全库的手写编号一起清掉，没打开的文件没法撤销。
