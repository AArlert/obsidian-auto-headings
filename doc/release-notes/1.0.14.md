## Comment blocks skipped & a clean way to leave / 注释块跳过与一条干净的离场路

**English**

- **Headings inside comment blocks are now skipped**: `#` lines inside `%%…%%` and `<!-- -->` are no longer treated as headings — not numbered, and they don't consume a counter slot either, so commenting a section out no longer shifts every number after it. Fence-vs-comment precedence, inline `%%` on a heading line, unclosed comments and other edge cases are all pinned down by tests. Together with the "No numbering" pseudo-template from 1.0.13, both of Number Headings' longest-standing open requests are now covered here.
- **Freeze numbering and release ownership (entire vault)** — a new entry in Settings → sensitive operations. It **keeps every number** exactly as it is, as ordinary text, removes only the invisible markers, and stops all automatic numbering from then on. This is for "I like my numbering, I just don't want a plugin managing it anymore" and for "I'm uninstalling but want to keep the result". Markers are removed vault-wide **including inside link anchors**, so `[[note#heading]]` links keep resolving. Like the vault-wide clear, it is deliberately not a command-palette command, and it asks for confirmation first.
- While numbering is released, the General settings tab shows a banner with a **Resume managing numbering** button — the plugin never silently does nothing.
- **Docs**: the Pandoc export path has now actually been tested (pandoc 3.10). A working filter ships at `assets/pandoc/strip-autoheadings.lua` — it strips the plugin's prefixes so `--number-sections` gives clean single numbering, or with `-M autoheadings=strip-marker` keeps your numbers and drops only the invisible character. Inline formatting inside headings survives either way. The Dataview guidance has been corrected: there is no `file.headers` field in Dataview, so the query this README used to suggest never worked; see the [marker character contract](../marker-contract.md#dataview) for what actually does.

**中文**

- **注释块内的标题不再被编号**：`%%…%%` 与 `<!-- -->` 内的 `#` 行不再视为标题——不编号，也**不占计数器槽位**，所以注释掉一节不会再让后面所有编号整体错位。围栏与注释的优先级、标题行尾的行内 `%%`、未闭合注释等十条边界都有测试钉死。加上 1.0.13 的「不编号」伪模板，Number Headings 久拖未决的两条呼声在本插件都已覆盖。
- **固化编号并交还所有权（全库）**——设置 → 敏感操作新增一项。它**原样保留全部编号**、只把不可见标记移除，此后插件停止一切自动编号。适合「喜欢现在的编号，只是不想再被插件管着」以及「准备卸载但要留住编号成果」。标记是全库移除的，**包括写在内部链接锚点里的**，所以 `[[笔记#标题]]` 仍能正常解析。与清除全库一样刻意不做成命令面板命令，且需二次确认。
- 交还所有权期间，全局设置页会显示提示条与**「恢复接管」**按钮——插件不会在你不知情的时候一声不吭地什么都不做。
- **文档**：Pandoc 导出路径这次真的实测过了（pandoc 3.10）。仓库内置可用的 `assets/pandoc/strip-autoheadings.lua`——默认剥掉插件前缀，让 `--number-sections` 编出单层干净编号；加 `-M autoheadings=strip-marker` 则保留你的编号、只去掉那个不可见字符。两种模式下标题里的内联格式都完好。Dataview 的建议也已订正：Dataview **没有** `file.headers` 字段，README 此前推荐的那条查询从来就不可能生效，真正可用的写法见[标记字符契约](../marker-contract.md#dataview)。

---

**Upgrade note / 升级说明**

Nothing changes in your files on upgrade. The comment-block rule only affects future renumbering; a heading that was numbered *before* being commented out will have its leftover prefix tidied up on the next renumber (comment blocks only — code fences are left byte-for-byte alone, so a code sample demonstrating the marker format is never rewritten).

升级本身不改动你的任何文件。注释块规则只影响此后的重排；**先被编号、后被包进注释块**的标题，其残留前缀会在下次重排时顺手清掉（仅限注释块——围栏代码块逐字节不动，演示标记格式的代码样例不会被改写）。
