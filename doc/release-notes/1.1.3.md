## Community Hub review fixes / Community Hub 审核修复

**English**

Maintenance release addressing findings from Obsidian's automated Community Hub code checker. No user-facing behavior changes.

- Replaced direct `.style.*` assignments with Obsidian's `setCssStyles` helper (clipboard-copy fallback textarea, path-suggestion popup positioning).
- Replaced a few remaining raw `document.createElement`/`activeDocument.createElement` calls with Obsidian's `createEl` helper where the created element is attached to the plugin's own DOM tree.
- The `editor-paste` handler now checks `evt.defaultPrevented` and calls `evt.preventDefault()` directly in its registered callback (previously delegated to an internal helper), so the checker's static analysis can see the guard. The underlying guard logic — which paste attempts get restored — is unchanged and covered by the existing test suite.

A couple of checker findings were intentionally left as-is, with the reasoning recorded in code comments and `doc/log.md`: one detached-DOM-node case where switching helpers would have broken test injectability without a corresponding runtime benefit, and the newer declarative settings-search API (`getSettingDefinitions`), which is a larger migration deferred to a future cycle.

**中文**

维护性发布，修复 Obsidian Community Hub 自动代码检查报告的问题，**不涉及任何用户可见行为变化**。

- 用 Obsidian 的 `setCssStyles` 助手替换直接 `.style.*` 赋值（剪贴板复制回退用的临时文本框、路径建议弹窗定位）。
- 把几处仍在用原生 `document.createElement`/`activeDocument.createElement` 的地方，在元素本就要挂进插件自身 DOM 树的场景下换成 Obsidian 的 `createEl` 助手。
- `editor-paste` 处理逻辑现在直接在注册的回调里判断 `evt.defaultPrevented` 并调用 `evt.preventDefault()`（此前委托给内部私有方法），让检查工具的静态分析看得见这层判断；实际决定「哪些粘贴会被还原」的守卫逻辑未变，且有现有单测覆盖。

有两处检查项经权衡后特意保留现状，理由记在代码注释与 `doc/log.md` 里：一处是分离 DOM 节点场景（换用助手会牺牲单测可注入性、却没有对应的运行时收益），另一处是较新的声明式设置搜索 API（`getSettingDefinitions`），属于更大的迁移工作，留给后续周期。
