# 1. 核心理念：状态转移测试

单测「干净输入 → 一次编号」容易，但真实使用是一条**时间线**：

```
裸标题 ──触发──▶ 已编号A ──改配置──▶ 再触发──▶ 已编号B ──……
```

每次触发 = **先剥离旧前缀、再写新前缀**。大多数诡异 bug 出在「剥离」一步：旧前缀用旧配置写入，剥离器拿新配置认不出，导致 `一、一 标题`、`第1 1 标题` 等叠加。

**因此，凡是模板字段可被用户改动，都要测状态转移**：对每个字段构造「用配置 X 编号 → 改字段为 Y → 再触发」，断言只剩一层正确前缀。

> **幂等性总断言**：`renumber(renumber(x)) === renumber(x)`，对几乎所有场景成立。

> **「2024 折中」与 WJ 根治**
>
> 无状态纯文本引擎无法区分「`1 ` 是插件前缀」与「`2024 ` 是用户正文」——形状相同（`数字+空格+文字`）。
>
> **0.3.18 折中**：剥离只剥最左侧一个完整前缀单元，其后内容一律当正文保留。`2024 总结` 首次仍被剥成 `1 总结`（已知取舍 E5），但 `1 2024 总结` 会**稳定保留**（E5b）。两项工程支撑：① 段间「序号间隔符」容差类**排除空格**；② **不再循环重剥**。
>
> **0.6.4 根治**：`buildPrefix` 在前缀末尾追加 Word Joiner（U+2060），`stripPrefix` WJ 快速路径精确截断——`1 ⁠2024 总结` 中 WJ 是精确边界，完全幂等。旧格式（无 WJ）仍由正则路径向后兼容。

> **写场景的要诀**：永远多想一步「**之前是什么状态**」。同样一个「把序号样式改成中文」，在空文件上做没问题，在已编号文件上做就可能炸——后者才是用户的真实路径。**每条配置变更场景都应配一条「先用旧配置编号 → 改 → 再触发」的状态转移用例。**
