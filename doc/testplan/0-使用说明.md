# 0. 使用说明

## 0.1 读者与用途

| 读者 | 看什么 | 怎么用 |
|------|--------|--------|
| **开发 Agent** | 状态列**非 ✅** 的行 | ❌ = 已知 bug，补 `dev_tests/` 回归测试后修复；🔲 = 场景已定但无测试，补测试 |
| **手动实测用户** | 操作步骤 + 预期结果 | 照步骤在真实 Vault 操作，不符即 bug，记录到 `doc/log.md` |
| **写规格 Agent** | 相关场景组文件 | 改 `spec/` 某节时核对：新规格是否让预期变化或制造新状态转移坑 |

## 0.2 与 `tests/` 的关系

- **`tests/dev_tests/*.test.ts`**：自动化单元测试（Vitest，`npm test`）。标 **dev** 的场景最终需有对应断言；行内 `→ dev_tests/xxx.test.ts` 标注归属文件。
- **`tests/user_tests/*.md`**：可粘贴进 Obsidian 实测的样例。标 **user** 的场景需有对应 `.md`（先写「场景 + 预期」，再给可复制代码块）。
- 一条场景可**同时**是 dev + user。

> 加场景、补测试、回填状态的先后顺序是开发流程的一部分，唯一出处是
> [`dev-cycle` 技能](../../.claude/skills/dev-cycle/SKILL.md)，此处不复述。

## 0.3 状态图例

| 标记 | 含义 |
|------|------|
| ✅ | 行为正确，dev_tests 已覆盖 |
| ❌ | 已知 bug，待修 |
| ⚠️ | 设计取舍——有意为之，勿误修 |
| 🔲 | 预期已定，尚无测试覆盖 |

## 0.4 默认模板基线（除非场景另注）

阿拉伯数字 · 序号间隔符 `.` · 标题间隔符**空格** · `topLevel=H2` · `skipFill=补 0` ·
`ancestorNumeral=self` · 各级 `inherit=true` · 白名单 `目录/附录/参考文献`（全部匹配）。
