# 5. 维护工作流程

通用开发周期（先加场景 → 补测试 → 全绿 → 回填 → 记忆 → bump → docs → 提交）的**唯一事实源是根
[`CLAUDE.md`](../../CLAUDE.md) §4**，此处不复述。本文档特有的补充规则：

- **动了编号引擎**（`numbering.ts` 家族 / `parser.ts`）时额外跑 `npm run test:fuzz`；修好已登记 bug 后**放开 `uvm/framework.ts` 里对应约束**，放开后仍绿才算修彻底。
- **回填状态**（🔲/❌ → ✅ + 根因/备注）时同步更新 §3 已知 bug 汇总表。
- 状态计数与待办清单**跑 `npm run docs` 看摘要**（只统计 §2 场景清单区间），不必整读本文档。

> **写场景的要诀**：永远多想一步「**之前是什么状态**」。同样一个「把序号样式改成中文」，在空文件上做没问题，在已编号文件上做就可能炸——后者才是用户的真实路径。**每条配置变更场景都应配一条「先用旧配置编号 → 改 → 再触发」的状态转移用例。**
