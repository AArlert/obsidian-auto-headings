# tests/probes — 真机时序探查

单测模拟不了的东西（Obsidian 的建议框调度、和别的插件抢弹框位、输入法拼字与上屏、插件加载顺序）放在这里，
在真实 Obsidian 里跑。脚本是「函数体」写法（顶层 `await`、`return`），返回 `{ pass, fails, results }`。

| 脚本                | 覆盖                                                                                                        | 前提                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `suggest-timing.js` | 标题链接建议 × Various Complements：英文键入的不同节奏、输入法拼字后上屏、VC 关了再开（testplan Q41 / Q44） | 库里装着本插件新构建与 VC 的插件文件（可停用）；「建议显示在」为本插件的建议框 |
| `suggest-rules.js`  | 触发规则与排序、标题行只排除自己、重名笔记写路径、VC 词条按实时索引过滤（testplan Q7 / Q27–Q34 / Q46–Q48）  | 库里装着本插件新构建；不需要 VC。临时文件夹 `探针-AH规则` 结束时删除           |

## 怎么跑

需要一个能在 Obsidian 里执行任意 JS 的通道，且**只用于测试库**（不要在日常使用的库里跑），例如一个只装在测试库里、
监视某个文件并执行其内容的开发用小插件，或 Obsidian CLI 的 `eval`（适合短脚本）。把脚本内容交给它执行，读回返回值。

窗口要在前台（脚本会先 `focus()`）；输入法拼字靠 CDP 的 `Input.imeSetComposition` 模拟，脚本结束会
`detach` 调试器、删掉临时文件夹 `探针-AH时序`、恢复 VC 原来的启用状态。
